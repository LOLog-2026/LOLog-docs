# 요구사항

사용자나 서비스가 무엇을 할 수 있어야 하는지만 적었어요. 어떤 기술로 만드는지는 아래 기술 요구사항에, 어떻게 동작하는지는 [기능 명세](functional-spec.md)에 있어요.

## 기술 요구사항

| ID | 영역 | 요구사항 |
| --- | --- | --- |
| TR-01 | 앱 | Android 앱(Android만, iOS는 하지 않음). 언어는 Kotlin |
| TR-02 | 앱 | 글자 변환은 폰 안에서 sherpa-onnx로 한다. 음성 구간 감지(VAD)로 말소리 구간만 넘기고, 링버퍼로 구간 앞의 소리를 더 붙여 말이 잘리지 않게 한다. 백그라운드 녹음은 포그라운드 서비스로 돌린다.글자 변환 품질에 따라 다른 stt엔진으로 변경 고려 |
| TR-03 | 교육기관 서버 | Nginx가 HTTPS 공개 주소를 맡고 경로로 나눈다(/auth → 인증, /api → 메인 백엔드). 게이트웨이는 두지 않는다 |
| TR-04 | 교육기관 서버 | 인증 서비스와 메인 백엔드는 Spring Boot(Java)로 만들고, 각자 토큰을 검사한다. 토큰은 JWT, 비밀번호는 BCrypt 해시로 저장한다 |
| TR-05 | 교육기관 서버 | 작업 큐는 Redis Streams(detect, comic). 작업 상태의 기준은 DB에 둔다 |
| TR-06 | 교육기관 서버 | PostgreSQL에 사용자·카드·작업 상태·임시 대화 텍스트를, SeaweedFS(S3 호환)에 완성된 만화 이미지를 둔다(추후 음성 파일도) |
| TR-07 | Jetson | Python 추론 워커가 큐에서 작업을 꺼내 처리한다. LLM은 Jetson에서 직접 돌리고 OpenAI 호환 주소로 부른다. 이야기 감지와 화자 구분은 LLM이 문맥으로 한다. 그림 모델은 글자와 말풍선 없이 그리고, 말풍선과 한글 대사는 워커가 코드로 그려 넣는다 |
| TR-08 | Jetson | LLM과 FLUX.2 klein + LoRA는 번갈아 올린다. 올라가 있는 모델로 할 수 있는 일을 먼저 다 처리하고 바꾼다. 만화는 콘티(LLM)와 그림(FLUX) 단계로 나눠, LLM이 올라가 있을 때 기다리는 만화의 콘티를 모두 만들고 FLUX로 바꿔 그림을 한꺼번에 그린다. 다른 모델의 일이 너무 오래 기다리면 바꾼다(만화는 사용자가 기다리므로 한도를 더 짧게). 몇 개를 모을지와 기다리는 한도는 처리 시간을 재 보고 정한다 |
| TR-09 | 연구실 서버 | FLUX.2 klein LoRA를 간단한 그림체·캐릭터 위주로 학습해 가중치를 Jetson에 올린다. 다른 모델(LLM, STT)은 학습하지 않고 프롬프트와 모델 선택으로 맞춘다. LLM 품질이 모자라면 모델을 먼저 바꾸고, LLM 파인튜닝은 P2로 미룬다 |
| TR-10 | 연결 | Jetson은 교육기관 서버에 SSH 터널로 붙는다. Redis는 밖에 열지 않고, 끊기면 다시 붙게 한다 |
| TR-11 | 알림 | 푸시 알림은 FCM으로 보낸다 |
| TR-12 | 보안 | 대화 텍스트와 음성을 외부 회사로 보내지 않는다. 보관함은 본인만 볼 수 있다 |

## 미정 항목

- **처리 방식:** Jetson 모델 바꾸는 규칙의 숫자(몇 개 모아 처리할지, 다른 모델의 일을 얼마나 기다리게 할지). 규칙의 틀은 TR-08에 정함. Jetson에서 모델을 올리는 시간과 처리 시간을 재 보고 정한다
