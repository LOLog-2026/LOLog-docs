# 요구사항

사용자나 서비스가 무엇을 할 수 있어야 하는지만 적었어요. 어떤 기술로 만드는지는 아래 기술 요구사항에, 어떻게 동작하는지는 [기능 명세](functional-spec.md)에 있어요.

## 기능 요구사항

### 인증

| ID | 요구사항 | 확인 기준 | 우선순위 | 비고 |
| --- | --- | --- | --- | --- |
| FR-AUTH-01 | 사용자는 이메일과 비밀번호로 가입하고 로그인할 수 있다 | 메일로 받은 인증번호를 넣어야 가입된다. 가입한 이메일로 로그인된다. 이미 가입된 이메일(소셜 로그인으로 가입한 경우 포함)로는 다시 가입되지 않고 안내가 나온다 | P0 | 인증번호는 SMTP 메일로 보내요 |
| FR-AUTH-02 | 사용자는 구글·네이버 계정으로 로그인할 수 있다 | 두 계정 모두로 로그인된다. 처음 로그인하면 가입도 같이 된다. 그 계정의 이메일로 이미 가입된 계정이 있으면 새 계정을 만들지 않고 안내가 나온다 | P0 | 이메일 제공 동의는 필수. 카카오는 이메일 동의항목에 비즈 앱 심사가 필요해 이번 범위에서 뺌(2026-11-09). 다시 넣을 때는 이메일 없이 받는 설계부터 정한다 |
| FR-AUTH-03 | 사용자는 한 번 로그인하면 앱을 다시 열어도 로그인 상태가 유지된다 | 앱을 껐다 켜도 다시 로그인하지 않아도 된다 | P0 |  |
| FR-AUTH-04 | 사용자는 로그아웃할 수 있다 | 로그아웃한 폰에서는 내 보관함이 보이지 않고 알림도 오지 않는다 | P0 |  |
| FR-AUTH-05 | 사용자는 회원 탈퇴할 수 있다 | 회원 정보는 소프트 삭제되고, 그 사용자의 카드·만화 이미지·대화 텍스트·작업 기록·푸시 토큰은 모두 지워진다 | P0 | 보낸 오류 신고·의견만 예외로 남고 보낸 사람이 비워져요(FR-FEEDBACK-01) |
| FR-AUTH-06 | 사용자는 내 계정에 구글·네이버 계정을 연결해 그 계정으로도 로그인할 수 있고, 연결을 끊을 수 있다 | 연결한 소셜 계정으로 로그인하면 같은 계정(같은 보관함)으로 들어간다. 끊으면 그 소셜 계정으로는 이 계정에 들어오지 않는다. 비밀번호가 없는 계정의 마지막 소셜 연결은 끊지 않고 안내한다 | P0 | 계정 합치기는 없음. 연결할 소셜 계정이 이미 다른 계정(이메일·소셜 모두)에 붙어 있으면 409 SOCIAL\_ALREADY\_LINKED로 그 계정을 탈퇴한 뒤 연결하라고 안내한다(화면 문구는 functional-spec FR-AUTH-06). 두 계정을 그대로 따로 써도 된다 |
| FR-AUTH-07 | 사용자는 이메일 계정의 비밀번호를 잊었을 때 찾고, 로그인한 뒤 바꿀 수 있다 | 이메일로 받은 안내로 새 비밀번호를 정할 수 있다. 로그인한 상태에서 지금 비밀번호를 넣고 새 비밀번호로 바꿀 수 있다 | P1 | 메일 인증번호(가입과 같은 규칙)로 새 비밀번호를 정한다. 소셜로만 가입해 비밀번호가 없는 계정은 대상이 아니다. 비밀번호를 바꾸면 다른 기기의 로그인은 끊긴다 |

| TR-01 | 앱 | Android 앱(Android만, iOS는 하지 않음). 언어는 Kotlin |
| TR-02 | 앱 | 글자 변환은 폰 안에서 sherpa-onnx로 한다. 음성 구간 감지(VAD)로 말소리 구간만 넘기고, 링버퍼로 구간 앞의 소리를 더 붙여 말이 잘리지 않게 한다. 백그라운드 녹음은 포그라운드 서비스로 돌린다. 모델은 SenseVoice int8(2024-07-17)이다. fp32·Whisper small·한국어 Zipformer·잡음 제거(GTCRN)·SenseVoice 2025판과 비교해 정했다([측정 결과](https://github.com/LOLog-2026/LOLog-ai/tree/develop/experiments/261109-stt-ondevice)). 설정값은 FR-REC-03에 있다. 글자 변환 품질에 따라 다른 STT 엔진으로 바꾸는 것도 고려한다 |
| TR-03 | 교육기관 서버 | Nginx가 HTTPS 공개 주소를 맡고 경로로 나눈다(/auth → 인증, /api → 메인 백엔드). 게이트웨이는 두지 않는다 |
| TR-04 | 교육기관 서버 | 인증 서비스와 메인 백엔드는 Spring Boot(Java)로 만들고, 각자 토큰을 검사한다. 토큰은 JWT, 비밀번호는 BCrypt 해시로 저장한다 |
| TR-05 | 교육기관 서버 | 작업 큐는 Redis Streams(detect, comic, video). video는 Jetson 3호가 읽는다([카드 영상](video.md)). 작업 상태의 기준은 DB에 둔다 |
| TR-06 | 교육기관 서버 | PostgreSQL에 사용자·카드·작업 상태·임시 대화 텍스트를, 교육기관 MinIO(S3 호환, storage.java21.net)에 완성된 만화 이미지를 둔다(추후 음성 파일도) |
| TR-07 | Jetson | Python 추론 워커가 큐에서 작업을 꺼내 처리한다. LLM은 Jetson에서 직접 돌리고 OpenAI 호환 주소로 부른다. 이야기 감지와 화자 구분은 LLM이 문맥으로 한다. 그림 모델은 글자와 말풍선 없이 그리고, 말풍선과 한글 대사는 워커가 코드로 그려 넣는다 |
| TR-08 | Jetson | Jetson 두 대에 역할을 나눈다. 1호는 LLM을 올리고 감지 작업을, 2호는 FLUX.2 klein + LoRA를 올리고 만화 작업을 맡는다. 만화 콘티는 2호 워커가 1호의 LLM을 불러 만든다. 모델을 번갈아 올리지 않는다 |
| TR-09 | 연구실 서버 | FLUX.2 klein LoRA를 간단한 그림체·캐릭터 위주로 학습해 가중치를 Jetson에 올린다. 다른 모델(LLM, STT)은 학습하지 않고 프롬프트와 모델 선택으로 맞춘다. LLM 품질이 모자라면 모델을 먼저 바꾸고, LLM 파인튜닝은 P2로 미룬다 |
| TR-10 | 연결 | Jetson은 교육기관 서버에 SSH 터널로 붙는다. Redis는 밖에 열지 않고, 끊기면 다시 붙게 한다 |
| TR-11 | 알림 | 푸시 알림은 FCM으로 보낸다 |
| TR-12 | 보안 | 대화 텍스트와 음성을 외부 회사로 보내지 않는다. 보관함은 본인만 볼 수 있다 |
