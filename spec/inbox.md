# 알림 목록과 공지사항 (초안)

설정 옆 종 버튼으로 들어가는 화면과, 앱 안에서 새로 온 것을 점으로 보여 주는 기능이에요. 화면에는 전체, 공지사항, 알림 탭이 있어요. 화면은 앱에서 만들어요. 공지사항을 쓰고 고치는 것은 [관리자](admin.md)에 있어요.

- 이름이 "(초안)"인 주소·필드는 구현하면서 바뀌어도 돼요

## 1. 알림 목록

- 푸시를 보낼 때 같은 내용을 서버에 한 줄 남겨요. 푸시가 안 가도 목록에는 남아요
- 지금 있는 푸시 여섯 가지(`CARDS_CREATED`, `COMIC_DONE`, `COMIC_FAILED`, `PROFILE_CHARACTER_READY`, `PROFILE_CHARACTER_FAILED`, `FRIEND_REQUEST`)를 모두 남겨요. 앞으로 새 푸시 종류가 생기면 그것도 남겨요. 방 푸시([친구와 같이 쓰는 방](rooms.md)의 초대, 내 만화에 달린 댓글, 해산)도 남겨요
- 방 대화는 푸시가 없어서 목록에도 없어요. 방 목록의 받지 않은 글 수로만 보여요
- 문구는 지금 푸시처럼 앱이 `type`과 값으로 만들어요. 서버는 문구를 저장하지 않아요. 대사는 넣지 않아요(FR-NOTI-03)
- 친구 요청 알림은 요청이 취소되거나 거절돼도 그대로 둬요. 눌렀을 때 요청이 없으면 친구 화면으로 가요
- 30일이 지나면 지워요

## 2. 공지사항

- 모든 사용자에게 같은 글이 보여요. 제목과 본문이 있어요
- 새 공지사항은 푸시로 알리지 않아요(모든 사용자에게 한꺼번에 보내는 코드가 없어요)

## 3. 탭과 읽음

- 전체 탭은 공지사항과 알림을 시간 순서로 섞어서 보여 줘요. 주소 하나가 탭 값에 따라 걸러서 줘요
- 읽음은 알림마다 둬요. 누른 알림만 읽음이 되고, 화면 위 "모두 읽음" 버튼을 누르면 지금까지 온 것이 모두 읽음이 돼요
- 공지사항도 글마다 읽음을 둬요(초안)
- 종 버튼의 점은 안 읽은 알림이나 공지사항이 하나라도 있으면 보여요

## 4. 앱 안 새 소식 표시

- 지금은 알림창에 우리 앱 알림이 남아 있는 동안 안드로이드가 앱 아이콘에 점을 보여 줘요. 앱 안에는 새로 온 것을 보여 주는 표시가 없어요
- 앱 안에서 기능마다 새로 온 게 있으면 점을 보여 주고, 그 화면을 열면 사라져요. 점을 둘 곳은 여섯 군데예요

| 곳 | 점이 생기는 때 |
| --- | --- |
| 보관함 | 새 카드 |
| 만화 | 완성·실패 |
| 프로필 캐릭터 | 다 만듦·실패 |
| 친구 | 친구 요청 |
| 친구 방 | 초대, 내 만화에 달린 댓글, 해산, 받지 않은 글 |
| 종 버튼 | 위 전부와 공지사항 |

- 새 푸시가 생기면 그 기능 화면에 점을 더해요
- 서버는 `GET /api/me/badges` 하나로 기능별 있음·없음을 줘요(초안). 친구 요청은 받은 요청 수, 방은 받지 않은 글 수(지금 있음)로 정해요. 보관함·만화·프로필 캐릭터는 기능마다 "마지막으로 본 시각"을 두고 그 뒤에 온 알림이 있는지로 정해요
- 화면을 열면 앱이 `POST /api/me/badges/{kind}/read`를 불러요(초안)

### 알림창 맞추기

- 푸시를 띄울 때 알림에 꼬리표(`friend`, `room:{id}`, `cards`, `comic:{id}`)를 달아 둬요(초안)
- 앱에서 그 화면을 열면 같은 꼬리표 알림을 알림창에서 지워요(`NotificationManager.cancel`). 알림이 없어지니 아이콘 점도 같이 사라져요
- 앱 안에서 알림을 누르면 알림창의 같은 알림도 지워요
- 알림창에서 밀어서 지우기만 하면 앱 안 점은 남아요. 아직 확인한 게 아니니까요
- 아이콘에 점 대신 숫자를 보여 주는 폰도 있는데, 숫자는 폰(런처) 설정을 따라요

## 5. API

모두 `/api`(메인 백엔드)이고 로그인이 필요해요.

| 메서드 | 주소 | 하는 일 | 요청 | 응답 |
| --- | --- | --- | --- | --- |
| GET | /api/inbox | 목록. 최근 것이 위 | 쿼리 `tab`(`ALL`·`NOTICE`·`NOTIFICATION`), `cursor` | 200 `{ items: List<InboxItem>, nextCursor }` |
| GET | /api/inbox/unread | 종 버튼의 점 | - | 200 `{ hasUnread }` |
| POST | /api/inbox/{kind}/{id}/read | 하나 읽음. kind는 `notice`·`notification` | - | 204 |
| POST | /api/inbox/read | 모두 읽음 | - | 204 |
| GET | /api/me/badges | 기능별 새 소식 있음·없음(초안) | - | 200 Badges |
| POST | /api/me/badges/{kind}/read | 그 화면을 열었음(초안) | - | 204 |

**InboxItem**

| 필드 | 타입 | 필수 | 설명 |
| --- | --- | --- | --- |
| kind | String | O | `NOTICE`·`NOTIFICATION` |
| id | Long | O | 공지사항 ID 또는 알림 ID |
| createdAt | DateTime | O | |
| read | Boolean | O | |
| notice | Object | null 가능 | 공지사항이면 `{ title, body }` |
| notification | Object | null 가능 | 알림이면 `{ type, data }`. data는 푸시에 넣은 값 그대로 |

**Badges**(초안): `{ cards, comics, profileCharacter, friends, rooms, inbox }`, 값은 모두 Boolean. kind는 이 이름과 같아요.

## 6. DB

[DB](db.md) 메인 백엔드 V9(`notices`, `notifications`, `notice_reads`, `badge_reads`)에 있어요. 탈퇴하면 그 회원의 `notifications`·`notice_reads`·`badge_reads`를 지워요.
