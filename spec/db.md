# DB (메인 백엔드)

업데이트 기능 중 친구 등록, 음성 저장, 순간 다시 듣기, 캐릭터(프로필 캐릭터 포함), 카드 고치기 넓히기에 필요한 DB 변경과, 그 변경을 지금 DB 구조에 합친 전체 구조예요. 친구와 같이 쓰는 방은 아직 설계 중이라 이 문서에 넣지 않았어요.

- 메인 백엔드(lolog-api) 테이블이에요. 인증 DB(lolog-auth의 `users`, `social_accounts`)는 관리자 기능(아래 인증 V4, 구현됨)에서만 바뀌어요
- 인증과 메인 백엔드는 같은 스키마를 써요([배포 설정](deployment.md) 4장). 새 테이블 이름은 인증 테이블과 겹치지 않아요
- 회원은 지금처럼 `user_id`(인증 DB의 `users.id`)로 가리키고 외래 키는 걸지 않아요
- 카드 고치기 넓히기(화자 더하기·빼기)는 DB 변경이 없어요. 지금 `card_speakers`·`card_lines`로 돼요

## 1. 바뀌는 것

## 2. 마이그레이션

지금 lolog-api에는 V1~V14, 인증 서비스(lolog-auth)에는 V1~V4가 있고 모두 구현됐어요. 글로 만화·영상 만들기의 V15·V16은 lolog-api PR #73·#74에 있어요(머지 전, 아래 "글로 만화·영상 만들기"). 아래는 V5부터 적었어요. 캐릭터(V7)는 친구(V5)의 `user_profiles`에 열을 더해서 V5 다음이에요.

```sql
ALTER TABLE recording_audio_files ADD CONSTRAINT fk_recording_audio_files_recordings FOREIGN KEY (recording_id) REFERENCES recordings (id) ON DELETE CASCADE;

ALTER TABLE recordings ADD COLUMN ended_at TIMESTAMPTZ;
ALTER TABLE recordings ADD COLUMN audio_saved BOOLEAN NOT NULL DEFAULT FALSE;
-- 이미 있는 녹음: 시작 시각에 받은 묶음 길이를 더해 채운다
```

### V8__rooms.sql (초안)

[친구와 같이 쓰는 방](rooms.md)의 표예요. 방·올린 만화·좋아요·대화는 외래 키로 이어서, 방을 지우면(마지막 멤버가 나감) 모두 지워지고 만화를 지우면 그 만화를 올린 기록과 좋아요·대화 줄이 지워져요. 회원은 지금처럼 외래 키 없이 `user_id`로 가리켜요.

```sql
-- 친구와 같이 쓰는 방: 방, 멤버, 올린 만화, 좋아요, 대화
CREATE TABLE rooms (
    id BIGINT NOT NULL GENERATED BY DEFAULT AS IDENTITY,
    name VARCHAR(20) NOT NULL,
    created_by BIGINT NOT NULL,
    last_activity_at TIMESTAMPTZ,
    created_at TIMESTAMPTZ NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMPTZ NOT NULL DEFAULT CURRENT_TIMESTAMP,
    CONSTRAINT rooms_pk PRIMARY KEY (id)
);
CREATE TABLE room_members (
    room_id BIGINT NOT NULL,
    user_id BIGINT NOT NULL,
    last_read_at TIMESTAMPTZ NOT NULL DEFAULT CURRENT_TIMESTAMP,
    created_at TIMESTAMPTZ NOT NULL DEFAULT CURRENT_TIMESTAMP,
    CONSTRAINT room_members_pk PRIMARY KEY (room_id, user_id)
);
CREATE TABLE room_posts (
    id BIGINT NOT NULL GENERATED BY DEFAULT AS IDENTITY,
    room_id BIGINT NOT NULL,
    comic_id BIGINT NOT NULL,
    user_id BIGINT NOT NULL,
    created_at TIMESTAMPTZ NOT NULL DEFAULT CURRENT_TIMESTAMP,
    CONSTRAINT room_posts_pk PRIMARY KEY (id),
    CONSTRAINT uk_room_posts_room_id_comic_id UNIQUE (room_id, comic_id)
);
CREATE TABLE room_post_likes (
    post_id BIGINT NOT NULL,
    user_id BIGINT NOT NULL,
    created_at TIMESTAMPTZ NOT NULL DEFAULT CURRENT_TIMESTAMP,
    CONSTRAINT room_post_likes_pk PRIMARY KEY (post_id, user_id)
);
CREATE TABLE room_messages (
    id BIGINT NOT NULL GENERATED BY DEFAULT AS IDENTITY,
    room_id BIGINT NOT NULL,
    user_id BIGINT NOT NULL,
    message_type VARCHAR(10) NOT NULL,
    post_id BIGINT,
    body VARCHAR(200),
    created_at TIMESTAMPTZ NOT NULL DEFAULT CURRENT_TIMESTAMP,
    CONSTRAINT room_messages_pk PRIMARY KEY (id),
    CONSTRAINT ck_room_messages_type CHECK (message_type IN ('CREATED', 'POSTED', 'LIKED', 'COMMENT')),
    CONSTRAINT ck_room_messages_body CHECK ((message_type = 'COMMENT') = (body IS NOT NULL)),
    CONSTRAINT ck_room_messages_post CHECK (message_type IN ('CREATED', 'COMMENT') OR post_id IS NOT NULL)
);

ALTER TABLE room_members ADD CONSTRAINT fk_room_members_rooms FOREIGN KEY (room_id) REFERENCES rooms (id) ON DELETE CASCADE;
ALTER TABLE room_posts ADD CONSTRAINT fk_room_posts_rooms FOREIGN KEY (room_id) REFERENCES rooms (id) ON DELETE CASCADE;
ALTER TABLE room_posts ADD CONSTRAINT fk_room_posts_comics FOREIGN KEY (comic_id) REFERENCES comics (id) ON DELETE CASCADE;
```

### 글로 만화·영상 만들기 (초안)

업데이트 설계_v3 1-1·1-2 탭의 표예요. SQL은 [글로 만화·영상 만들기](texts.md#7-db-초안) 7장에 있어요. lolog-api가 `V15__texts.sql`(texts, cards·jobs 바꾸기, PR #73)과 `V16__blogs.sql`(blog_sources·blog_posts, texts.blog_post_id 외래 키, PR #74)로 구현했어요(11-13, 머지 전). 아래 3장 전체 구조에는 cards의 바뀐 열만 적었어요.

- 새 표: `blog_sources`(등록한 블로그), `blog_posts`(가져온 블로그 글, `(user_id, guid)` 유일, 연결을 끊어도 남고 `source_id`만 NULL), `texts`(카드로 만들 글, `source` = `BLOG`·`WRITTEN`)
- `cards`: `text_id`를 더하고 `start_ms`·`end_ms`를 NULL 허용으로 바꿔요. 녹음 카드는 `recording_id`, 글 카드는 `text_id`를 가리켜요. 글 카드의 `recorded_at`은 직접 쓴 글이면 `texts.created_at`, 블로그 글이면 `blog_posts.published_at`(없으면 가져온 시각 `blog_posts.created_at`)이에요
- `jobs`: `text_id`를 더하고 작업 종류에 `TEXT`를 더해요(`ck_jobs_type`·`ck_jobs_target` 같이 고침)
- 카드를 지우면 그 `texts` 줄도 지워요. 블로그 글은 카드가 생기면 `texts.body`를 NULL로 비워요
- `blog_sources`는 `(user_id, feed_url)` 유일, 플랫폼 칸 없음. 글 상태는 칸 없이 카드·`jobs`로 채워요
- 탈퇴(`UserDataService`)에 더할 것: `texts`, `blog_posts`, `blog_sources`(`blog_posts`는 SET NULL이라 따로 지움)

## 4. 쓸 때 주의할 것

실제 PostgreSQL 16에 V1~V7과 인증 V1~V3을 차례로 적용하고, 데이터가 있는 DB에서도 돌려 보며 확인한 것이에요.

- **화자를 빼고 key를 다시 매길 때:** `card_speakers`에 `UNIQUE (card_id, speaker_key)`가 있어서, 화자2를 빼고 화자3을 화자2로 바꿀 때 바꾸기를 먼저 하면 유일 제약에 걸려요. 뺄 화자 줄을 먼저 지우고(flush) 그다음 남은 화자와 대사의 key를 바꿔요
- **프로필 캐릭터를 찾을 때:** `card_speakers.character_id`는 글자예요. 기본 화자 id(`young-f-02`)도 들어가서 `character_id::bigint`로 바꾸면 오류가 나요. `user_profiles.user_id::text = character_id`로 맞춰요
- **캐릭터가 빠질 때:** 친구 끊기·차단·캐릭터 지우기·탈퇴 때 `character_type = 'PROFILE' AND character_id = '회원 ID'`인 줄의 두 열을 NULL로 바꿔요. 끊기·차단은 두 사람이 서로의 카드에서 빠지니 카드 주인(`cards.user_id`)도 같이 봐요. 이 조건을 위해 부분 인덱스 `idx_card_speakers_profile_character`를 둬요
- **친구 요청:** 같은 두 사람 사이에는 줄이 하나예요(`uk_friendships_pair`). 상대가 이미 나에게 요청했으면 새 줄을 넣지 않고 그 줄을 `ACCEPTED`로 바꿔요
- **음성 파일 다시 올리기:** 같은 `(recording_id, seq)`를 다시 올리면 덮어써요(`ON CONFLICT ... DO UPDATE`)
- **카드 음성 상태:** `cards.audio_key`가 있으면 `READY`, 없고 `recordings.audio_saved`가 true이며 `ended_at`에서 7일이 안 지났으면 `PENDING`, 나머지는 `NONE`이에요. 녹음이 지워져 `cards.recording_id`가 NULL이면 `NONE`이에요
- **`recordings.ended_at`:** 글 묶음을 받을 때마다 시작 시각 + 받은 묶음 길이의 합으로 고쳐 적어요. 끝 묶음이 안 와도 7일을 셀 수 있어요
- **탈퇴(`UserDataService`)에 더할 것:** `friendships`(요청한 쪽·받은 쪽 모두), `user_blocks`(한 쪽·당한 쪽 모두), `user_profiles` 줄을 지우고, 다른 사람 카드에 붙은 이 회원의 프로필 캐릭터를 NULL로 바꿔요. `recording_audio_files`는 녹음을 지우면 같이 지워져요(ON DELETE CASCADE). 음성·프로필 그림 파일은 `users/{userId}/` 아래라 지금 저장소 삭제 코드로 지워져요
- **AVATAR 작업:** 대상이 `jobs.user_id`(그 회원의 프로필 캐릭터)라 `comic_id`·`recording_part_id`는 둘 다 NULL이에요. 탈퇴하면 지금처럼 `jobs`를 `user_id`로 지워서 같이 지워져요
