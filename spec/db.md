# DB (메인 백엔드)

업데이트 기능 중 친구 등록, 음성 저장, 순간 다시 듣기, 캐릭터(프로필 캐릭터 포함), 카드 고치기 넓히기에 필요한 DB 변경과, 그 변경을 지금 DB 구조에 합친 전체 구조예요. 친구와 같이 쓰는 방은 아직 설계 중이라 이 문서에 넣지 않았어요.

- 모두 메인 백엔드(lolog-api) 테이블이에요. 인증 DB(lolog-auth의 `users`, `social_accounts`)는 바뀌지 않아요
- 인증과 메인 백엔드는 같은 스키마를 써요([배포 설정](deployment.md) 4장). 새 테이블 이름은 인증 테이블과 겹치지 않아요
- 회원은 지금처럼 `user_id`(인증 DB의 `users.id`)로 가리키고 외래 키는 걸지 않아요
- 카드 고치기 넓히기(화자 더하기·빼기)는 DB 변경이 없어요. 지금 `card_speakers`·`card_lines`로 돼요

## 1. 바뀌는 것

새 테이블 5개, 열을 더하는 테이블 4개예요.

| 기능 | 새 테이블 | 있는 테이블에 더하는 것 |
| --- | --- | --- |
| [친구](friends.md) | `user_profiles`(닉네임·친구 코드), `friendships`(친구 관계·요청), `user_blocks`(차단) | - |
| [음성 저장](audio.md) | `recording_audio_files`(10분 단위 음성 파일) | `recordings.ended_at`, `recordings.audio_saved`, `cards.audio_key` |
| [순간 다시 듣기](replay.md) | - | `cards.audio_duration_ms` |
| [캐릭터](characters.md) | `default_characters`(기본 화자 목록) | `user_profiles.character_*` 5개, `card_speakers.character_type`·`character_id`, `jobs`의 작업 종류에 `AVATAR` |
| [카드 고치기](api-dto.md) | - | - |

## 2. 마이그레이션

메인 백엔드의 다음 번호는 V5예요(지금 V1~V4). 구현 순서대로 세 개로 나눠요. 순서만 지키면 번호는 구현할 때 바뀌어도 돼요. 캐릭터(V7)는 친구(V5)의 `user_profiles`에 열을 더하니 V5 다음이어야 해요.

### V5__friends.sql

```sql
-- 친구 등록: 회원 프로필, 친구 관계·요청, 차단
CREATE TABLE user_profiles (
    user_id BIGINT NOT NULL,
    nickname VARCHAR(10),
    friend_code VARCHAR(8) NOT NULL,
    created_at TIMESTAMPTZ NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMPTZ NOT NULL DEFAULT CURRENT_TIMESTAMP,
    CONSTRAINT user_profiles_pk PRIMARY KEY (user_id),
    CONSTRAINT uk_user_profiles_friend_code UNIQUE (friend_code)
);
CREATE TABLE friendships (
    id BIGINT NOT NULL GENERATED BY DEFAULT AS IDENTITY,
    requester_id BIGINT NOT NULL,
    addressee_id BIGINT NOT NULL,
    status VARCHAR(10) NOT NULL DEFAULT 'PENDING',
    created_at TIMESTAMPTZ NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMPTZ NOT NULL DEFAULT CURRENT_TIMESTAMP,
    CONSTRAINT friendships_pk PRIMARY KEY (id),
    CONSTRAINT ck_friendships_status CHECK (status IN ('PENDING', 'ACCEPTED')),
    CONSTRAINT ck_friendships_not_self CHECK (requester_id <> addressee_id)
);
CREATE TABLE user_blocks (
    blocker_id BIGINT NOT NULL,
    blocked_id BIGINT NOT NULL,
    created_at TIMESTAMPTZ NOT NULL DEFAULT CURRENT_TIMESTAMP,
    CONSTRAINT user_blocks_pk PRIMARY KEY (blocker_id, blocked_id),
    CONSTRAINT ck_user_blocks_not_self CHECK (blocker_id <> blocked_id)
);

CREATE UNIQUE INDEX uk_friendships_pair ON friendships (LEAST(requester_id, addressee_id), GREATEST(requester_id, addressee_id));
CREATE INDEX idx_friendships_addressee_id_status ON friendships (addressee_id ASC, status ASC);
CREATE INDEX idx_friendships_requester_id_status ON friendships (requester_id ASC, status ASC);
CREATE INDEX idx_user_blocks_blocked_id ON user_blocks (blocked_id ASC);

COMMENT ON TABLE user_profiles IS '회원 프로필-----닉네임과 친구 코드. 처음 프로필을 볼 때 만들어짐';
COMMENT ON COLUMN user_profiles.user_id IS '회원 ID-----인증 DB 회원 ID(외래 키 아님)';
COMMENT ON COLUMN user_profiles.nickname IS '닉네임-----1~10자. 아직 안 정했으면 NULL. 겹쳐도 됨';
COMMENT ON COLUMN user_profiles.friend_code IS '친구 코드-----대문자·숫자 8자리(0·O·1·I·L 제외). 프로필을 만들 때 서버가 발급하고 바뀌지 않음';
COMMENT ON COLUMN user_profiles.created_at IS '생성 일시';
COMMENT ON COLUMN user_profiles.updated_at IS '수정 일시';
COMMENT ON TABLE friendships IS '친구 관계-----친구 요청과 친구. 두 사람 사이에 줄 하나. 거절·취소·끊기는 줄을 지움';
COMMENT ON COLUMN friendships.id IS '친구 관계 ID';
COMMENT ON COLUMN friendships.requester_id IS '요청한 회원 ID';
COMMENT ON COLUMN friendships.addressee_id IS '요청받은 회원 ID';
COMMENT ON COLUMN friendships.status IS '상태-----PENDING(요청 중), ACCEPTED(친구)';
COMMENT ON COLUMN friendships.created_at IS '생성 일시-----요청한 시각';
COMMENT ON COLUMN friendships.updated_at IS '수정 일시-----ACCEPTED가 된 뒤에는 친구가 된 시각';
COMMENT ON TABLE user_blocks IS '차단-----차단한 사람과 차단된 사람';
COMMENT ON COLUMN user_blocks.blocker_id IS '차단한 회원 ID';
COMMENT ON COLUMN user_blocks.blocked_id IS '차단된 회원 ID';
COMMENT ON COLUMN user_blocks.created_at IS '생성 일시-----차단한 시각';
```

### V6__audio.sql

```sql
-- 음성 저장·순간 다시 듣기
CREATE TABLE recording_audio_files (
    id BIGINT NOT NULL GENERATED BY DEFAULT AS IDENTITY,
    recording_id BIGINT NOT NULL,
    seq INTEGER NOT NULL,
    audio_key VARCHAR(255) NOT NULL,
    start_ms BIGINT NOT NULL,
    end_ms BIGINT NOT NULL,
    created_at TIMESTAMPTZ NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMPTZ NOT NULL DEFAULT CURRENT_TIMESTAMP,
    CONSTRAINT recording_audio_files_pk PRIMARY KEY (id),
    CONSTRAINT uk_recording_audio_files_recording_id_seq UNIQUE (recording_id, seq),
    CONSTRAINT ck_recording_audio_files_seq CHECK (seq >= 1),
    CONSTRAINT ck_recording_audio_files_range CHECK (start_ms >= 0 AND start_ms < end_ms)
);
ALTER TABLE recording_audio_files ADD CONSTRAINT fk_recording_audio_files_recordings FOREIGN KEY (recording_id) REFERENCES recordings (id) ON DELETE CASCADE;

ALTER TABLE recordings ADD COLUMN ended_at TIMESTAMPTZ;
ALTER TABLE recordings ADD COLUMN audio_saved BOOLEAN NOT NULL DEFAULT FALSE;
-- 이미 있는 녹음: 시작 시각에 받은 묶음 길이를 더해 채운다
UPDATE recordings r SET ended_at = r.started_at + make_interval(secs => COALESCE(
    (SELECT SUM(p.duration_sec) FROM recording_parts p WHERE p.recording_id = r.id), 0));

ALTER TABLE cards ADD COLUMN audio_key VARCHAR(255);
ALTER TABLE cards ADD COLUMN audio_duration_ms BIGINT;
ALTER TABLE cards ADD CONSTRAINT ck_cards_audio CHECK ((audio_key IS NULL) = (audio_duration_ms IS NULL));

COMMENT ON TABLE recordings IS '녹음-----녹음 하나(최장 3시간). 글은 묶음(recording_parts)에, 음성은 음성 파일(recording_audio_files)에 있음';
COMMENT ON TABLE recording_audio_files IS '녹음 음성 파일-----10분 단위로 올라온 전체 녹음 파일. 녹음이 끝난 때부터 7일 뒤 파일과 함께 지움';
COMMENT ON COLUMN recording_audio_files.id IS '음성 파일 ID';
COMMENT ON COLUMN recording_audio_files.recording_id IS '녹음 ID';
COMMENT ON COLUMN recording_audio_files.seq IS '파일 번호-----녹음 안에서 1부터. 글 묶음 번호와 따로 감';
COMMENT ON COLUMN recording_audio_files.audio_key IS '음성 오브젝트 키';
COMMENT ON COLUMN recording_audio_files.start_ms IS '시작 시각(ms)-----녹음 시작부터';
COMMENT ON COLUMN recording_audio_files.end_ms IS '끝 시각(ms)';
COMMENT ON COLUMN recording_audio_files.created_at IS '생성 일시';
COMMENT ON COLUMN recording_audio_files.updated_at IS '수정 일시-----같은 번호를 다시 올리면 바뀜';
COMMENT ON COLUMN recordings.ended_at IS '녹음 끝 시각-----시작 시각 + 받은 묶음 길이의 합. 묶음을 받을 때마다 고쳐 적음. 7일을 세는 기준';
COMMENT ON COLUMN recordings.audio_saved IS '음성 저장 여부-----이 녹음에서 음성 저장을 켰는지. 글 묶음을 올릴 때 받음';
COMMENT ON COLUMN cards.audio_key IS '카드 구간 음성 오브젝트 키-----음성이 없으면 NULL. 카드를 지울 때 파일도 지움';
COMMENT ON COLUMN cards.audio_duration_ms IS '카드 구간 음성 길이(ms)-----앞뒤 여유 0.5초씩 포함';
```

- 이미 있는 녹음의 `ended_at`은 V6에서 시작 시각에 받은 묶음 길이를 더해 채워요. 이미 있는 녹음은 `audio_saved`가 false라 음성 상태가 `NONE`이에요
- 기본 화자 24명은 마이그레이션에 넣지 않아요. 그림을 저장소에 올린 뒤 목록을 넣어요([캐릭터](characters.md) 2장). 넣는 값은 `characters.json` 그대로이고, 키는 `defaults/characters/{id}.png`·`defaults/characters/{id}_thumb.webp`예요

## 3. 전체 구조

V1~V7을 모두 적용한 메인 백엔드 테이블이에요. "변경" 칸의 "추가"는 이번에 더하는 열이에요.

### recordings (녹음)

녹음 하나(최장 3시간). 글은 묶음(recording_parts)에, 음성은 음성 파일(recording_audio_files)에 있음

| 열 | 타입 | 필수 | 설명 | 변경 |
| --- | --- | --- | --- | --- |
| id | BIGINT | O | 녹음 ID (자동 번호) |  |
| user_id | BIGINT | O | 회원 ID. 인증 DB 회원 ID(외래 키 아님) |  |
| client_recording_id | VARCHAR(64) | O | 앱 녹음 ID |  |
| started_at | TIMESTAMPTZ | O | 녹음 시작 시각 |  |
| status | VARCHAR(20) | O | 상태 기본값 RECEIVED |  |
| created_at | TIMESTAMPTZ | O | 생성 일시 |  |
| updated_at | TIMESTAMPTZ | O | 수정 일시 |  |
| ended_at | TIMESTAMPTZ | NULL 가능 | 녹음 끝 시각. 시작 시각 + 받은 묶음 길이의 합. 묶음을 받을 때마다 고쳐 적음. 7일을 세는 기준 | 추가 |
| audio_saved | BOOLEAN | O | 음성 저장 여부. 이 녹음에서 음성 저장을 켰는지. 글 묶음을 올릴 때 받음 기본값 false | 추가 |

- 검사 `ck_recordings_status`: `CHECK ((status IN ('RECEIVED', 'DETECTING', 'DONE', 'FAILED')))`
- 기본 키 `recordings_pk`: `PRIMARY KEY (id)`
- 유일 `uk_recordings_user_id_client_recording_id`: `UNIQUE (user_id, client_recording_id)`

### recording_parts (녹음 묶음)

1시간마다(그리고 끝날 때) 올라온 글 묶음. 문장은 감지 후 지움

| 열 | 타입 | 필수 | 설명 | 변경 |
| --- | --- | --- | --- | --- |
| id | BIGINT | O | 묶음 ID (자동 번호) |  |
| recording_id | BIGINT | O | 녹음 ID |  |
| part_no | INTEGER | O | 묶음 번호 |  |
| is_last | BOOLEAN | O | 마지막 묶음 여부 기본값 false |  |
| duration_sec | INTEGER | O | 묶음 길이(초) |  |
| sentences | JSON | NULL 가능 | 문장 목록. [{startMs, endMs, text}]. 감지 후 지움(넘길 끝부분만 다음 묶음 처리 뒤) |  |
| carry_from_ms | BIGINT | NULL 가능 | 다음 묶음으로 넘길 시작 시각(ms). 마지막 묶음이면 NULL |  |
| status | VARCHAR(20) | O | 상태 기본값 RECEIVED |  |
| created_at | TIMESTAMPTZ | O | 생성 일시 |  |
| updated_at | TIMESTAMPTZ | O | 수정 일시 |  |

- 검사 `ck_recording_parts_part_no`: `CHECK ((part_no >= 1))`
- 검사 `ck_recording_parts_status`: `CHECK ((status IN ('RECEIVED', 'DETECTING', 'DONE', 'FAILED')))`
- 외래 키 `fk_recording_parts_recordings`: `FOREIGN KEY (recording_id) REFERENCES recordings(id) ON DELETE CASCADE`
- 기본 키 `recording_parts_pk`: `PRIMARY KEY (id)`
- 유일 `uk_recording_parts_recording_id_part_no`: `UNIQUE (recording_id, part_no)`
- 인덱스 `idx_recording_parts_recording_id`: `(recording_id)`

### recording_audio_files (녹음 음성 파일) — 새 표

10분 단위로 올라온 전체 녹음 파일. 녹음이 끝난 때부터 7일 뒤 파일과 함께 지움

| 열 | 타입 | 필수 | 설명 | 변경 |
| --- | --- | --- | --- | --- |
| id | BIGINT | O | 음성 파일 ID (자동 번호) |  |
| recording_id | BIGINT | O | 녹음 ID |  |
| seq | INTEGER | O | 파일 번호. 녹음 안에서 1부터. 글 묶음 번호와 따로 감 |  |
| audio_key | VARCHAR(255) | O | 음성 오브젝트 키 |  |
| start_ms | BIGINT | O | 시작 시각(ms). 녹음 시작부터 |  |

## 4. 쓸 때 주의할 것

실제 PostgreSQL 16에 V1~V7과 인증 V1~V3을 차례로 적용하고, 데이터가 있는 DB에서도 돌려 보며 확인한 것이에요.

- **화자를 빼고 key를 다시 매길 때:** `card_speakers`에 `UNIQUE (card_id, speaker_key)`가 있어서, 화자2를 빼고 화자3을 화자2로 바꿀 때 바꾸기를 먼저 하면 유일 제약에 걸려요. 뺄 화자 줄을 먼저 지우고(flush) 그다음 남은 화자와 대사의 key를 바꿔요
- **프로필 캐릭터를 찾을 때:** `card_speakers.character_id`는 글자예요. 기본 화자 id(`young-f-02`)도 들어가서 `character_id::bigint`로 바꾸면 오류가 나요. `user_profiles.user_id::text = character_id`로 맞춰요
- **캐릭터가 빠질 때:** 친구 끊기·차단·캐릭터 지우기·탈퇴 때 `character_type = 'PROFILE' AND character_id = '회원 ID'`인 줄의 두 열을 NULL로 바꿔요. 끊기·차단은 두 사람이 서로의 카드에서 빠지니 카드 주인(`cards.user_id`)도 같이 봐요. 이 조건을 위해 부분 인덱스 `idx_card_speakers_profile_character`를 둬요
- **친구 요청:** 같은 두 사람 사이에는 줄이 하나예요(`uk_friendships_pair`). 상대가 이미 나에게 요청했으면 새 줄을 넣지 않고 그 줄을 `ACCEPTED`로 바꿔요
- **음성 파일 다시 올리기:** 같은 `(recording_id, seq)`를 다시 올리면 덮어써요(`ON CONFLICT ... DO UPDATE`)
- **카드 음성 상태:** `cards.audio_key`가 있으면 `READY`, 없고 `recordings.audio_saved`가 true이며 `ended_at`에서 7일이 안 지났으면 `PENDING`, 나머지는 `NONE`이에요. 녹음이 지워져 `cards.recording_id`가 NULL이면 `NONE`이에요
- **`recordings.ended_at`:** 글 묶음을 받을 때마다 시작 시각 + 받은 묶음 길이의 합으로 고쳐 적어요. 끝 묶음이 안 와도 7일을 셀 수 있어요
- **탈퇴(`UserDataService`)에 더할 것:** `friendships`(요청한 쪽·받은 쪽 모두), `user_blocks`(한 쪽·당한 쪽 모두), `user_profiles` 줄을 지우고, 다른 사람 카드에 붙은 이 회원의 프로필 캐릭터를 NULL로 바꿔요. `recording_audio_files`는 녹음을 지우면 같이 지워져요(ON DELETE CASCADE). 음성·프로필 그림 파일은 `users/{userId}/` 아래라 지금 저장소 삭제 코드로 지워져요
