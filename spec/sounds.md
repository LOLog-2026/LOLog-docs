# 쇼츠 효과음·배경음 (FR-EXT-03, 제안)

업데이트 설계_v4 2번 탭(음성·배경 공개 API)과 2-1번 탭(효과음 벡터 검색)이에요. **정함**은 지원이 정한 것, **Claude가 정함**은 지원이 맡겨서 Claude가 정한 백엔드 설계예요. 표시가 없는 것은 Claude 초안이에요. 워커와 맞닿는 곳(콘티 칸, 소리 찾기 요청·응답)은 AI 담당 확인에 따라 바뀔 수 있어요.

## 1. 정한 것

### 정함 11-14, 지원

- 효과음·배경음은 Freesound에서 **CC0 소리만** 미리 모아 두고 써요. 쇼츠를 만들 때마다 외부 API를 부르지 않아요
- 라이선스는 CC0만 써요. 출처 표기 없이 쓸 수 있어요. LOLog는 누구나 APK를 받을 수 있지만 수익이 없는 비상업 프로젝트예요
- 대사 목소리는 지금처럼 Jetson TTS 그대로예요. 공개 TTS API는 쓰지 않아요(대화가 외부 회사로 나가지 않게)

### 정함 11-24, 지원: 벡터 검색으로 바꿈

- 소리 고르기를 **정해진 검색어 값 고르기에서 벡터 검색으로** 바꿔요. 콘티가 장면 소리를 영어 한 줄로 적으면, api가 그 글과 가장 가까운 **소리 자체**를 찾아요
- 모델은 CLAP(`laion/clap-htsat-unfused`, 소리·글 모두 512차원)이에요
- 저장하는 벡터는 **소리 벡터만**이에요. 설명 글 벡터는 두지 않아요
- 저장·검색은 **pgvector**예요. 서버 PostgreSQL에 pgvector를 깔아야 해요(인프라)
- Freesound에는 따로 문의하지 않아요(학교 프로젝트)

왜 바꾸나:

- 소리를 몇천 개로 늘리면 콘티가 고를 검색어 목록을 api와 ai에 똑같이 들고 있기 어려워요
- Freesound 제목·태그가 엉성해도 소리 자체로 찾을 수 있어요
- 검색어는 Freesound에서 모아 올 때만 쓰고, 콘티와는 상관없어져요

CLAP 라이선스(11-24 확인): 코드 CC0 1.0, Hugging Face 모델 카드 Apache 2.0(같은 카드의 인용은 CC BY 4.0이라 엇갈림), 학습 데이터 라이선스는 못 찾았어요. 비상업 제한은 없어요.

## 2. 흐름

1. **모으기(지원 맥, 한 번씩):** 수집 스크립트가 넓은 검색어로 Freesound CC0 소리를 받고, CLAP 소리 쪽으로 벡터를 만들어 api에 넣어요
2. **콘티(Jetson 1호 LLM):** 영상 콘티 장면마다 `sfx`(장면에 맞는 소리를 영어 한 줄로, 없으면 null), 영상 하나에 `bgm`(분위기에 맞는 음악을 영어 한 줄로, 없으면 null)을 더해요(AI 담당, 쓰는 규칙은 [6장](#6-ai-쪽-민주), [영상 콘티](video.md#5-영상-콘티))
3. **찾기(Jetson 3호 → api):** 워커가 그 글을 `POST /internal/sounds/search`로 보내면, api가 CLAP 글 쪽으로 벡터를 만들어 pgvector에서 가까운 소리를 돌려줘요. 워커는 그중 하나를 videoId로 골라요(같은 영상은 늘 같은 소리)
4. **섞기(Jetson 3호):** 지금과 같아요. 워커가 소리를 받아 대사 wav 위에 numpy로 섞어(대사가 나오면 배경음을 줄이는 덕킹) wav 하나로 만들고, `video_render.py`의 ffmpeg에 넘겨요

- 오가는 건 "door slamming" 같은 소리 설명 한 줄뿐이고, 대사·대화 내용은 오가지 않아요

## 3. 모을 양

- 모으는 검색어 200개쯤: 생활 소리, 사람 반응, 동물, 탈것, 날씨, 장소 분위기, 만화 효과음, 음악 분위기 갈래별로
- 검색어마다 평점·다운로드 수 높은 순으로 10~20개, 효과음 5초 이하·배경음 30~60초
- 합쳐 3,000개쯤, 미리 듣기 ogg로 600MB쯤. Freesound는 하루 2,000번이라 이틀쯤 걸려요
- 같은 소리가 여러 검색어에 걸리면 `freesound_id`로 한 번만 넣어요
- Freesound에는 쓸 만한 CC0 배경음악이 적을 수 있어요. 모아 보고 적으면 배경음 검색어를 늘리거나 줄여요

## 5. 백엔드 설계

### DB

지금 있는 표(V19, Claude가 정함 11-14, lolog-api #87):

```sql
CREATE TABLE sound_library (
    id BIGINT NOT NULL GENERATED BY DEFAULT AS IDENTITY,
    kind VARCHAR(5) NOT NULL,              -- SFX(효과음), BGM(배경음)
    query VARCHAR(30) NOT NULL,            -- 검색어 값(door_slam 등)
    title VARCHAR(200),                    -- Freesound 제목
    object_key VARCHAR(255) NOT NULL,      -- defaults/sounds/{id}.ogg
    duration_ms INT NOT NULL,
    freesound_id BIGINT NOT NULL,          -- 같은 소리를 두 번 넣지 않게
    source_url VARCHAR(500) NOT NULL,      -- Freesound 페이지(출처 기록)
    license VARCHAR(10) NOT NULL DEFAULT 'CC0',
    created_at TIMESTAMPTZ NOT NULL DEFAULT CURRENT_TIMESTAMP,
    CONSTRAINT sound_library_pk PRIMARY KEY (id),
    CONSTRAINT uk_sound_library_freesound_id UNIQUE (freesound_id),
    CONSTRAINT ck_sound_library_kind CHECK (kind IN ('SFX', 'BGM')),
    CONSTRAINT ck_sound_library_license CHECK (license = 'CC0')
);
CREATE INDEX idx_sound_library_kind_query ON sound_library (kind ASC, query ASC);
```

벡터 검색으로 더하는 것(V23, 초안):

```sql
CREATE EXTENSION IF NOT EXISTS vector;  -- 서버 PostgreSQL에 pgvector가 깔려 있어야 해요

ALTER TABLE sound_library ALTER COLUMN query TYPE VARCHAR(50);     -- 뜻이 "콘티 값" → "모을 때 쓴 검색어"로 바뀜
ALTER TABLE sound_library ADD COLUMN embedding vector(512);        -- CLAP 소리 벡터, 길이 1로 맞춰 넣음
ALTER TABLE sound_library ADD COLUMN embedding_model VARCHAR(100); -- 벡터를 만든 모델 이름
```

- 이미 넣은 소리는 벡터가 없어서 두 칸을 NULL 허용으로 더해요. 수집 스크립트를 다시 돌리면 같은 `freesound_id`로 덮어써 채워져요
- 검색은 `embedding_model`이 api 설정의 모델과 같은 줄만 봐요. 벡터는 같은 모델로 만든 것끼리만 비교할 수 있어서, 모델을 바꿔도 옛 벡터와 섞이지 않게 해요
- 벡터 인덱스(HNSW)는 만들지 않고, 검색할 때 소리를 모두 비교해요(Claude 의견 11-24). HNSW는 가까워 보이는 후보만 먼저 뽑고 `kind`·`embedding_model` 조건은 그 뒤에 걸러서, 수가 적은 배경음은 맞는 소리가 있어도 빈 결과가 나올 수 있어요. 3,000개쯤은 모두 비교해도 빠르고 결과가 정확해요. 소리가 수만 개로 늘면 그때 다시 봐요
- `idx_sound_library_kind_query`는 GET 목록을 지우면서 `V24__drop_sound_query_index.sql`로 지워요. `query` 칸은 모을 때 쓴 검색어 기록으로 남겨요
- 사람마다의 데이터가 아니라서 탈퇴로 지우지 않아요

### 저장

- MinIO `lolog-comics` 버킷 `defaults/sounds/{id}.ogg`. 기본 화자 그림(`defaults/characters/`)과 같은 자리예요
- 워커는 응답의 10분 서명 주소로 받아요. 서비스가 모아 둔 공용 파일이라 만화 그림·기본 화자 그림과 같은 방식이에요(사용자 원본은 api가 직접 주는 것과 나눔). 워커는 응답을 받자마자 쓰니 만료 걱정이 없어요

### /internal API (지금 /internal과 같은 인증)

| 메서드 | 주소 | 부르는 쪽 | 하는 일 | 본문 | 응답 |
| --- | --- | --- | --- | --- | --- |
| PUT | /internal/sounds/{freesoundId} | 수집 스크립트 | 소리 넣기·바꾸기(같은 freesoundId면 덮어씀) | multipart `file`(audio/ogg, 5MB 이하), `kind`, `query`, `title`, `durationMs`, `sourceUrl`, `license`(CC0만), `embedding`(숫자 512개 JSON 배열), `embeddingModel` | 200 `{ id }` |
| DELETE | /internal/sounds/{freesoundId} | 수집 스크립트 | 어울리지 않는 소리 빼기. 파일도 지움. 없어도 204 | - | 204 |
| POST | /internal/sounds/search | 워커(3호) | 설명 글과 가까운 소리 찾기 | `{ kind, text, limit }` | 200 `{ sounds: [ { id, kind, durationMs, distance, url } ] }` |

- PUT `query`: 모을 때 쓴 검색어, 영어 소문자·숫자·`_`, 1~50자. `kind`: `SFX`·`BGM`
- PUT `embedding`·`embeddingModel`: 벡터 길이가 512가 아니거나 모델 이름이 api 설정과 다르면 400 `INVALID_REQUEST`
- lolog-api #106 구현에서 정한 것(초안, Claude 11-24): PUT의 `embedding`·`embeddingModel`은 꼭 있어야 해요(벡터 없는 소리를 새로 넣지 않게). 숫자가 아닌 값, 무한대, 모두 0인 벡터도 400이에요. 마이그레이션은 `V23__sound_embedding.sql`이에요
- search `text`: 영어 1~200자(api는 앞뒤 빈칸을 뺀 길이만 보고 영어인지는 보지 않아요, 초안 Claude 11-24). `limit`: 1~10, 없으면 5. `kind`: `SFX`·`BGM`
- api가 `ORDER BY embedding <=> :v LIMIT :limit`(코사인 거리)로 인덱스 없이 모두 비교해 찾고, 종류별 설정값(`SOUND_SFX_MAX_DISTANCE`·`SOUND_BGM_MAX_DISTANCE`)보다 먼 소리는 빼요. 기준은 api가 쥔 모델에 딸린 값이라 api가 가져요. 비워 두면 거르지 않아요(초안 Claude 11-24, 값을 정하기 전에도 검색을 시험할 수 있게).
- 기준은 효과음·배경음 따로 둬요(지원 11-25). 모은 뒤 재 보니 배경음은 거리가 0.34~0.41에 몰리고, 효과음은 맞는 소리가 0.37~0.64에 퍼져 있어서 기준 하나로는 둘 다 맞출 수 없었어요. 값은 효과음 0.65, 배경음 0.5로 시작해요(Claude 의견 11-25, 시험 문장 21개로 잰 값이라 실제 콘티 글로 다시 봐요). 거리가 같으면 `id` 순서예요
- 맞는 소리가 없으면 빈 배열이에요(오류 아님). 워커는 그 장면을 소리 없이 만들어요(지금과 같음)
- 글 벡터 모델을 못 읽으면 503 `EMBEDDING_UNAVAILABLE`. 워커는 이것도 "소리 없이"로 처리해요. `SOUND_EMBED_MODEL_DIR`이 비었거나 파일을 못 읽어도 서버는 뜨고 검색만 503이에요. 못 읽었으면 1분 뒤 다음 검색 때 다시 읽어요(초안 Claude 11-24)
- 오류: 400 `INVALID_REQUEST`(빈 값, 길이 초과, kind·license·query 모양 틀림, 벡터 틀림), 413 `PAYLOAD_TOO_LARGE`
- lolog-api #87 구현에서 정한 것(초안, Claude 11-14): ogg인지는 첫 바이트 `OggS`로 봐요. `license`를 빼면 CC0로 보고, `title`은 200자에서 잘라요. `sourceUrl`은 http·https 주소만 받아요
- 앱용 /api는 없어요. 앱은 완성된 쇼츠만 봐요

### api 안에서 글 벡터 만들기

- CLAP 글 쪽(텍스트 인코더 + 투영)만 ONNX로 바꿔 두고, ONNX Runtime(Java `com.microsoft.onnxruntime`)과 토크나이저(DJL `ai.djl.huggingface:tokenizers`)로 돌려요. 나온 벡터는 길이 1로 맞춰요
- ONNX로 바꿀 때 투영(글 벡터를 소리 벡터와 같은 공간으로 옮기는 마지막 층)까지 꼭 넣어요. 빠져도 오류 없이 512개 숫자가 나오지만 소리 벡터와 비교할 수 없어서 엉뚱한 소리가 나와요
- 설정: `SOUND_EMBED_MODEL_DIR`(`text_model.onnx`, `tokenizer.json`), `SOUND_EMBED_MODEL_NAME`, `SOUND_SFX_MAX_DISTANCE`, `SOUND_BGM_MAX_DISTANCE`. 모델 파일은 레포에 넣지 않고 서버에 둬요([배포](deployment.md))
- 처음 검색 때 올려 두고 계속 써요. 메모리는 맥에서 잰 값으로 548MB 늘었어요(582MB → 1,130MB, 11-24). api jar는 74MB 커졌어요(148MB → 222MB)
- 토큰은 77개까지 써요(CLAP 글 쪽이 배운 길이). `scripts/export_clap_text.py`와 api가 같은 값이어야 해요
- 같은 설명 글이 자주 와서, 글 → 벡터를 작게 캐시해요(최근 500개)
- 테스트: `postgres:latest` → `pgvector/pgvector:pg17`(배포 postgres 17과 맞춤, 로컬 `compose.yaml`도 같음). 모델 파일 없는 테스트는 글 벡터 만들기를 가짜로 바꿔 끼워요. `ClapTextEmbedderTests`는 `SOUND_EMBED_MODEL_DIR`을 줄 때만 돌고, Java 결과가 PyTorch 결과(`reference.json`)와 같은지(코사인 0.9999 이상) 봐요

### 수집 스크립트 (지원 맥)

- 벡터를 만들려면 CLAP을 Python으로 돌려야 해서 `scripts/collect-sounds.sh`를 Python(`scripts/collect_sounds.py`)으로 바꿔요
- 순서: Freesound 검색(`license:"Creative Commons 0"`, 길이 조건, 다운로드 수 순) → 미리 듣기 ogg(고음질) 받기(원본 내려받기는 OAuth2가 필요해서) → 48kHz 모노로 바꿔 CLAP 소리 벡터 → `PUT /internal/sounds/{freesoundId}`
- CLAP(`clap-htsat-unfused`)은 소리를 10초까지만 봐요. 10초보다 긴 소리(배경음 30~60초)는 10초씩 잘라 조각마다 벡터를 만들고, 평균을 낸 뒤 길이 1로 맞춰 하나로 넣어요(Claude 의견 11-24). 앞 10초만 보면 조용한 도입부 때문에 곡 분위기가 잘못 담길 수 있어서예요
- 글 쪽 ONNX 파일은 `scripts/export_clap_text.py`가 한 번 만들어요(소리 벡터와 같은 모델이어야 해서). 만든 뒤 PyTorch와 같은 벡터를 내는지 확인하고, 그 폴더를 서버에 올려요
- lolog-api #106 구현에서 정한 것(초안, Claude 11-24): 검색어 목록은 `scripts/sound-queries.tsv`(210개 초안)이고 검색어마다 기본 15개예요. 넣은 freesoundId를 맥의 `~/.lolog-collect-sounds.txt`에 적어 두고 다음에 돌릴 때 건너뛰어서, 하루 한도에 걸리면 다음 날 같은 명령으로 이어서 돌려요. Python 라이브러리 버전은 `scripts/requirements-sounds.txt`예요
- 맥에서는 SSH 터널로 api /internal에 닿아요
- Freesound API 키는 지원 맥 환경 변수에만 두고 레포에 넣지 않아요

### 콘티 설명 글 규칙 (정함 11-24, 민주)

CLAP은 소리를 사람이 설명한 영어 캡션("a door slams shut")으로 배웠어요. 그래서 장면이 아니라 **귀에 들리는 소리**를 캡션처럼 짧게 써야 가까운 소리가 나와요.

- 들리는 소리만 써요. 소리를 내는 것과 그 동작(`a door slamming shut`). 장면·감정·생각·그림은 쓰지 않아요
- 영어 소문자 3~10단어, 한 줄에 소리 하나. 쉼표·"then"·"and"로 여러 소리를 잇지 않아요(벡터가 두 소리 사이에 찍혀 어느 쪽도 안 맞아요)
- "no", "without" 같은 부정을 쓰지 않아요(CLAP이 부정을 못 알아들어 "no music"이 오히려 음악 근처에 찍혀요)
- 이름·장소 이름·대사 내용·숫자를 쓰지 않아요. 서버로 나가는 글이라 대화 내용이 섞이면 안 되고, 검색에도 도움이 안 돼요
- 효과음(`sfx`)은 장면의 행동·반응에 딱 맞는 소리가 있을 때만, 영상 하나에 3개까지. 사람 한 명의 반응 소리(한숨, 헉)도 써요
- 배경음(`bgm`)은 음악으로 써요. 분위기·악기·빠르기를 넣어 "... music"(모아 둔 배경음이 30~60초 음악이라서)
- 맞는 소리가 없으면 null이에요(벡터 검색은 늘 가장 가까운 것을 돌려줘서, 억지로 쓰면 엉뚱한 소리가 들어가요)
- 프롬프트에 예시(효과음 25개, 배경음 5개)를 보여 줘요. 이 중에서 고르라는 게 아니라 이런 모양으로 쓰라는 것이고, lolog-api `scripts/sound-queries.tsv` 갈래(생활·사람 반응·동물·탈것·날씨·장소·만화 효과음 / 음악)에 맞췄어요

### 코드가 맞추는 것

- 응답 형식: `sfx`·`bgm`은 `{"type": "string", "pattern": "^[a-z][a-z '-]{2,59}$"}`(소리 없음은 `"none"` → null). 한글·숫자·대문자 이름이 출력 단계에서 막혀요
  - 길이를 묶지 않으면 Qwen3.5-4B가 `"none, none, none, …"`을 끝없이 써서 4,096토큰에서 잘렸어요(1호 시험 11-24, 카드 3장 모두)
  - 쉼표·마침표를 허용하면 `"a phone vibrating on a desk, then a loud alarm blaring, a teacher sighs"`처럼 소리를 나열했어요
- 다듬기(`sounds.clean_desc`): 소문자·공백 하나로 맞추고, 이어 쓴 소리는 첫 소리만 남겨요(쉼표·"then"·"followed by"·"while"·"and a…", 앞이 3단어 넘는 "and"). 60자에서 끊겨 남은 "on a" 같은 끝말도 지워요. 규칙에 안 맞으면 그 소리만 빼고 LLM에 다시 묻지 않아요(소리는 있으면 좋은 것, P2)
- 검사(`video_storyboard.validate`): `sfx`·`bgm`은 null이거나 위 규칙에 맞는 글이어야 해요
- 찾기(`worker/video.py` `add_sounds`): 설명 글마다 `POST /internal/sounds/search`를 `limit` 3으로 한 번 부르고, 그중 하나를 videoId로 골라요(같은 영상은 늘 같은 소리, 영상마다는 조금씩 다름)
- 404(search 없음)·503(`EMBEDDING_UNAVAILABLE`)·400·빈 배열·받기 실패는 모두 그 소리만 빼고 영상을 만들어요
- 로그: 설명 글은 LLM이 장면을 보고 쓴 글이라 남기지 않아요(TR-12). 고른 소리 `id`·`distance`와 개수만 남겨요

### 시험 (지어낸 카드 3장: 강아지와 택배 상자, 뒤집힌 우산, 교실 휴대폰 알람)

- 11-24 1호 LLM: 세 카드 모두 74~93초, LLM 한 번에 검사 통과. 나온 효과음은 `a dog barking`, `a loud wind howling`, `a group of people laughing`, `a phone ringing loudly`, `a heavy sigh`
- 11-25 3호에서 실제 api 검색까지(앱 없이 콘티 → search → 섞기 → wav, 대사 목소리는 뺌). 소리 3~4개씩 들어갔고, 들어 보니 장면에 맞았어요(민주)

| 카드 | 효과음 글 → 거리 | 배경음 거리 |
| --- | --- | --- |
| 강아지 | `a dog barking nervously` 0.46, `a group of people laughing` 0.45 | 0.44 |
| 우산 | `rain falling on a roof` 0.64, `a loud wind gust sound` 0.51, `people laughing and chatting in the background` 0.57 | 0.48 |

- 세 카드 모두 `bgm`을 프롬프트의 마지막 예시(`playful comedy music with pizzicato strings`) 그대로 썼어요. 웃긴 이야기라 어울리고 후보 3개 중 영상마다 골라서 그대로 뒀어요

## 7. 바꾸는 순서

1. 인프라(민주): 서버 PostgreSQL에 pgvector 깔기
2. api(지원): V23, PUT에 벡터 받기, search 새로. 이때 GET은 남겨 둬요(ai가 아직 GET을 씀)
3. 수집(지원): Python 스크립트로 3,000개쯤 모으고 기존 소리도 벡터 채우기 → distance 재서 거리 기준 정하기(11-25 2,441개 모음, 기준은 종류별로)
4. ai(민주): 콘티·워커를 설명 글 + search로(LOLog-ai #77, 11-25 Jetson 반영)
5. api(지원): GET 목록과 `idx_sound_library_kind_query` 지우기(ai #77이 main에 들어간 뒤, V24)

## 8. 정할 것

- 모을 검색어 목록과 개수(초안: lolog-api `scripts/sound-queries.tsv` 210개 × 15개)
- 거리 기준 값(시작: 효과음 0.65, 배경음 0.5). 실제 콘티 글로 만든 영상을 보고 조정. 11-25 콘티 글 3장으로 재 보니 효과음 0.35~0.64, 배경음 0.44~0.48이 모두 기준 안이었고 들어 보니 괜찮아서 그대로 둬요(민주, [6장](#6-ai-쪽-민주)). 비 소리(0.64)가 기준에 가까워, 어색한 효과음이 들리면 0.6쯤으로 낮춰 봐요
- 배경음에 음악용 CLAP을 따로 쓸지. 지금 모델은 일반 소리 위주로 배워서 음악 분위기를 잘 못 맞힐 수 있어요. 일단 모델 하나로 모은 뒤, 배경음 검색 결과를 들어 보고 정해요(모델을 둘로 나누면 api 메모리와 설정이 두 벌이 돼요). 11-25에 재 보니 "upbeat happy"에 잔잔한 피아노가 1등으로 나오는 등 분위기가 잘 안 맞았어요. 같은 날 콘티 글(`playful comedy music with pizzicato strings`)로 고른 배경음은 들어 보니 괜찮았어요(민주)
