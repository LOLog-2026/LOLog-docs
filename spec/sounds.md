# 쇼츠 효과음·배경음 (제안)

업데이트 설계_v4 2번 탭(음성·배경 공개 API)이에요. **정함**은 지원이 정한 것, **제안**은 AI 담당(민주)이 확인하고 정할 것, **Claude가 정함**은 지원이 맡겨서 Claude가 정한 백엔드 설계예요. 워커와 맞닿는 곳(콘티 칸, 검색 요청·응답)은 AI 담당 확인에 따라 바뀔 수 있어요.

## 1. 정한 것 (정함 11-14, 지원)

- 효과음·배경음은 Freesound에서 **CC0 소리만** 미리 모아 두고, **벡터 검색**으로 골라요. 쇼츠를 만들 때마다 외부 API를 부르지 않아요
- 라이선스는 CC0만 써요. 출처 표기 없이 쓸 수 있고, Freesound API 약관의 "임시 사본만" 규칙과도 부딪히지 않아요. LOLog는 누구나 APK를 받을 수 있지만 수익이 없는 비상업 프로젝트예요
- 대사 목소리는 지금처럼 Jetson TTS 그대로예요. 공개 TTS API는 쓰지 않아요(대화가 외부 회사로 나가지 않게)

## 2. 흐름 (제안)

1. **모으기(한 번):** 수집 스크립트가 Freesound에서 검색어마다 CC0 소리를 받고, CLAP 모델로 소리 벡터를 만들어 api에 넣어요
2. **콘티:** 영상 콘티 장면마다 `sfx`(어울리는 소리를 짧게 적은 영어 글, 없으면 null), 영상 하나에 `bgm`(분위기 영어 글, 없으면 null)을 더해요
3. **고르기:** 워커가 그 글을 `POST /internal/sounds/search`로 보내면, api가 글을 벡터로 바꿔 가장 가까운 소리를 돌려줘요
4. **섞기:** 워커가 소리를 받아 대사 wav 위에 numpy로 섞어(대사가 나오면 배경음을 줄이는 덕킹) wav 하나로 만들고, 지금처럼 `video_render.py`의 ffmpeg에 넘겨요. ffmpeg 명령은 그대로예요

- 벡터는 **백엔드 쪽에서** 만들어요(제안, 지원 동의). Jetson에 임베딩 모델을 더 올리면 메모리가 모자랄 수 있어서예요. 소리 벡터는 수집 때 한 번, 글 벡터는 api가 만들어요. 워커는 설명 글만 보내요
- 대사·대화 내용은 오가지 않고 "door slam" 같은 짧은 설명 글만 api로 가요
- CLAP는 영어로 학습돼서 콘티가 소리 설명을 영어로 적는 게 나아요

## 3. 모을 양 (제안)

- 태그는 고르는 목록이 아니라 모아 올 때 쓰는 검색어예요
- 효과음 검색어 25개쯤(문 닫힘, 발소리, 웃음, 박수, 폰 알림·진동, 키보드, 식기·컵, 자동차·경적, 비, 바람, 개, 고양이, 뿅, 실패음, 짠, 바둠츠, 휙, 쿵, 한숨, 카페 소음, 교실 소음 등), 배경음 분위기 5개(신남, 잔잔, 긴장, 슬픔, 코믹)
- 검색어마다 CC0 5~10개, 효과음 5초 이하·배경음 30~60초. 합쳐 200~300개, ogg로 100MB 아래
- Freesound에는 쓸 만한 CC0 배경음악이 적을 수 있어요. 모아 보고 적으면 배경음은 빼거나 나중에 넣어요

## 4. 나누는 범위 (제안)

| 누구 | 할 일 |
| --- | --- |
| 지원(api) | 수집 스크립트(받기·소리 벡터·넣기), `sound_library` 표 + pgvector, 소리 넣기·빼기 `/internal`, 글을 벡터로 바꾸는 검색 `/internal`(ONNX Runtime), MinIO 저장 |
| 민주(ai) | 콘티에 `sfx`·`bgm` 설명 글(영어) 넣기, 워커에서 검색 부르기·고르기, numpy로 대사 wav에 섞기·덕킹 |
| 민주(인프라) | 학교 서버 Postgres에 pgvector를 깔 수 있는지, 서버 CPU·메모리 여유(모델 0.5GB 안팎 추정) |

## 5. 백엔드 설계 (Claude가 정함 11-14, 지원이 맡김)

lolog-api develop(V16까지)의 패턴에 맞췄어요.

### DB (다음 Flyway 번호)

```sql
CREATE EXTENSION IF NOT EXISTS vector;   -- pgvector. 깔 권한이 있는지 인프라 확인

CREATE TABLE sound_library (
    id BIGINT NOT NULL GENERATED BY DEFAULT AS IDENTITY,
    kind VARCHAR(5) NOT NULL,              -- SFX(효과음), BGM(배경음)
    query VARCHAR(50) NOT NULL,            -- 모아 올 때 쓴 검색어
    title VARCHAR(200),                    -- Freesound 제목
    object_key VARCHAR(255) NOT NULL,      -- defaults/sounds/{id}.ogg
    duration_ms INT NOT NULL,
    freesound_id BIGINT NOT NULL,          -- 같은 소리를 두 번 넣지 않게
    source_url VARCHAR(500) NOT NULL,      -- Freesound 페이지(출처 기록)
    license VARCHAR(10) NOT NULL DEFAULT 'CC0',
    embedding vector(512) NOT NULL,        -- CLAP 소리 벡터, 길이 1로 맞춰 넣음
    embedding_model VARCHAR(100) NOT NULL, -- 벡터를 만든 모델 이름. 글 벡터 모델과 다르면 검색에서 빠짐
    created_at TIMESTAMPTZ NOT NULL DEFAULT CURRENT_TIMESTAMP,
    CONSTRAINT sound_library_pk PRIMARY KEY (id),
    CONSTRAINT uk_sound_library_freesound_id UNIQUE (freesound_id),
    CONSTRAINT ck_sound_library_kind CHECK (kind IN ('SFX', 'BGM')),
    CONSTRAINT ck_sound_library_license CHECK (license = 'CC0')
);
CREATE INDEX idx_sound_library_embedding ON sound_library USING hnsw (embedding vector_cosine_ops);
```

- 사람마다의 데이터가 아니라서 탈퇴로 지우지 않아요
- 300개쯤이면 인덱스 없이 다 비교해도 빠르지만, 늘어날 때를 생각해 HNSW를 둬요
- 시험: 지금 테스트는 `postgres:latest` 컨테이너라 pgvector가 없어요. `pgvector/pgvector` 이미지로 바꿔야 해요

### 저장

- MinIO `lolog-comics` 버킷 `defaults/sounds/{id}.ogg`. 기본 화자 그림(`defaults/characters/`)과 같은 자리예요
- 워커는 검색 응답의 10분 서명 주소로 받아요(만화 화자 그림 `imageUrl`과 같은 방식). 그래서 따로 "파일 받기" API는 두지 않아요

### /internal API (지금 /internal과 같은 인증)

| 메서드 | 주소 | 부르는 쪽 | 하는 일 | 본문 | 응답 |
| --- | --- | --- | --- | --- | --- |
| PUT | /internal/sounds/{freesoundId} | 수집 스크립트 | 소리 넣기·바꾸기(같은 freesoundId면 덮어씀) | multipart `file`(audio/ogg, 5MB 이하), `kind`, `query`, `title`, `durationMs`, `sourceUrl`, `license`(CC0만), `embedding`(숫자 512개 JSON 배열), `embeddingModel` | 200 `{ id }` |
| DELETE | /internal/sounds/{freesoundId} | 수집 스크립트 | 어울리지 않는 소리 빼기. 파일도 지움. 없어도 204 | - | 204 |
| POST | /internal/sounds/search | 워커(3호) | 설명 글로 가까운 소리 찾기 | `{ kind, text, limit }` | 200 `{ sounds: [ { id, kind, durationMs, distance, url } ] }` |

- `text`: 영어 설명 글, 1~200자. `limit`: 1~10, 없으면 5. `kind`: `SFX`·`BGM`
- api가 `text`를 CLAP 글 모델로 벡터로 바꾸고 `ORDER BY embedding <=> :v LIMIT :limit`(코사인 거리)로 찾아요. `embedding_model`이 지금 모델과 같은 줄만 봐요
- `sounds`는 가까운 순서예요. 같은 소리만 나오지 않게 그중 하나를 고르는 것(예: jobId로)과, 너무 먼 소리를 버릴 기준(distance)은 워커가 정해요
- 맞는 소리가 없으면 빈 배열이에요(오류 아님). 워커는 그 장면을 소리 없이 만들어요
- 오류: 400 `INVALID_REQUEST`(빈 값, 길이 초과, kind·license 틀림, 벡터가 512개가 아님, `embeddingModel`이 서버 모델과 다름), 413 `PAYLOAD_TOO_LARGE`, 503 `EMBEDDING_UNAVAILABLE`(모델 파일을 못 읽음)
- 앱용 /api는 없어요. 앱은 완성된 쇼츠만 봐요

### api 안 벡터 만들기

- 모델(추천): `laion/clap-htsat-unfused`(Hugging Face). 소리·글 모두 512차원이에요. 라이선스는 고를 때 확인 필요
- api에는 글 쪽(텍스트 인코더 + 투영)만 ONNX로 바꿔 두고, ONNX Runtime(Java, `com.microsoft.onnxruntime`)과 토크나이저(DJL `ai.djl.huggingface:tokenizers`)로 돌려요. 나온 벡터는 길이 1로 맞춰요
- 설정: `SOUND_EMBED_MODEL_DIR`(`text_model.onnx`, `tokenizer.json`), `SOUND_EMBED_MODEL_NAME`(= 수집 때 `embeddingModel`). 모델 파일은 레포에 넣지 않고 서버에 둬요
- 처음 검색 때 모델을 올려 두고 계속 써요. 메모리 0.5GB 안팎(추정, 측정 전)
- 모델 파일이 없으면 검색만 503이고 나머지는 돌아요

### 수집 스크립트 (지원 맥에서 한 번)

1. Freesound API로 검색어마다 `license:"Creative Commons 0"`와 길이 조건으로 찾기. 원본 내려받기는 OAuth2가 필요해서 미리 듣기 ogg(고음질)를 받아요
2. 같은 CLAP 모델의 소리 쪽으로 벡터 만들기(Python)
3. `PUT /internal/sounds/{freesoundId}`로 넣기. 맥에서는 SSH 터널로 api /internal에 닿아요
4. 글 모델 ONNX 파일도 같은 스크립트에서 한 번 만들어 서버에 올려요

- Freesound API 키는 지원 맥 환경 변수에만 두고 레포에 넣지 않아요
- 스크립트를 둘 레포(ai 레포 또는 api 레포 `scripts/`)는 정할 것이에요

## 6. 아직 정할 것

- 콘티 `sfx`·`bgm` 칸의 정확한 모양과 장면당 개수(AI 담당, [영상 콘티](video.md#5-영상-콘티))
- 섞는 크기·덕킹 정도, 앱에서 배경음 켜기·끄기를 둘지
- 학교 서버 pgvector 가능 여부. 안 되면 검색 방식을 다시 정해요
- 요구사항 번호(FR)는 아직 안 붙였어요
