# 음성 저장

녹음한 소리를 파일로 남겨 서버에 올리고, 보관하고, 지우는 기능이에요. 카드에서 그 소리를 듣는 화면과 API는 [순간 다시 듣기](replay.md)에 있어요.

- 사용자가 켰을 때만 음성을 저장해요. 기본값은 끔이에요
- 끄면 앱이 소리를 파일로 쓰지도 올리지도 않아요. 끈 동안 생긴 카드에는 음성이 없어요
- 전체 녹음 파일은 녹음이 끝난 때부터 7일 보관한 뒤 지워요
- 카드에 담긴 구간의 음성만 따로 잘라 카드가 있는 동안 둬요
- 쇼츠(FR-EXT-02)는 [카드 영상](video.md)에 있어요. 쇼츠는 저장한 음성을 쓰지 않고 대사를 TTS로 읽어요
- 재생 바로 구간 고르기는 이번 범위가 아니에요

## 1. 화면과 문구

화면을 어디에 둘지는 앱 담당과 정해요.

### 켜고 끄기

- 녹음 버튼이 있는 화면에 "음성도 저장" 체크가 있어요. 기본값은 끔이에요
- 한 번 고른 값은 폰이 기억해서 다음 녹음 때도 그대로 보여요
- 녹음 중에는 바꿀 수 없어요

### 모바일 데이터 창

- 녹음 동의 창([기능 명세](functional-spec.md) FR-REC-10)에서 "동의받음"를 누른 다음에 띄워요. 동의 창 본문은 "음성도 저장"을 켰는지에 따라 달라요
- 체크를 켠 채 모바일 데이터로 녹음을 시작하면 창을 띄워요. 녹음을 시작할 때만, 매번 물어요
- 문구: "모바일 데이터를 쓰고 있어요. 녹음한 음성을 지금 올릴까요, Wi-Fi에 연결되면 올릴까요?"
- 버튼: "지금 올리기", "Wi-Fi에서 올리기"
- "Wi-Fi에서 올리기"를 골라도 음성은 저장해요. 지금은 글만 올리고, 음성은 폰에 두었다가 Wi-Fi가 되면 올려요
- 녹음 중에 Wi-Fi에서 모바일 데이터로 바뀌어도 다시 묻지 않아요. 글은 계속 올리고, 그 뒤 음성은 폰에 두었다가 Wi-Fi가 되면 올려요

| 녹음 버튼을 누를 때 | 창 | 음성 |
| --- | --- | --- |
| 체크 꺼짐 | 안 뜸 | 저장하지 않음 |
| 체크 켜짐, Wi-Fi | 안 뜸 | 저장하고 바로 올림 |
| 체크 켜짐, 모바일 데이터 | 뜸. 둘 중 하나를 고름 | 저장함. "지금 올리기"면 바로 올리고, "Wi-Fi에서 올리기"면 폰에 두었다가 Wi-Fi에서 올림 |

"음성도 저장"을 끄는 것과 모바일 데이터 창에서 "Wi-Fi에서 올리기"를 고르는 것은 달라요. 앞은 음성을 아예 저장하지 않고, 뒤는 저장하되 나중에 올려요.

### 안내 문구

| 곳 | 음성 저장을 켰을 때 | 껐을 때 |
| --- | --- | --- |
| 녹음 중 상단 알림 | 대화를 글자로 바꾸고, 음성도 저장하고 있어요. | 대화를 글자로 바꾸고 있어요. 음성은 폰 밖으로 나가지 않아요. |
| 녹음 화면 아래 작은 글 | 카드에 담긴 음성만 남고, 나머지는 7일 뒤에 지워져요 | 음성 파일은 올리지 않아요 |

- 마이크 권한 안내는 체크를 고르기 전에 보여서 한 가지 문구만 써요. "대화를 녹음하면서 폰 안에서 바로 글자로 바꿔요. 음성 저장을 켜면 다시 듣기에 쓰려고 음성을 보관해요. 카드에 담긴 부분만 남기고 나머지는 7일 뒤에 지워요."

## 2. 음성 파일

### 형식

- AAC(ADTS, `.aac`), 16kHz, 모노, 32kbps로 시작해요. 폰에서 들어 보고 음질이 모자라면 올려요
- ADTS는 소리 조각(프레임)마다 머리말이 붙어 있어요. 앱이 중간에 죽어도 그때까지 쓴 부분은 들을 수 있어요
- 조각 하나가 0.064초로 일정해요. 서버는 카드 구간을 자를 때 조각만 골라내요
- 저장하는 소리는 글자 변환 앞에서 크기를 맞춘 소리예요(기능 명세 "글자 변환"의 크기 맞춤). 작게 녹음된 말도 고르게 들려요. 원래 마이크 소리로 되돌릴 수는 없어요

### 10분 단위 파일

- 음성 파일은 10분 단위로 나눠요. 파일 하나가 약 2.5MB이고, 3시간 녹음이면 18개예요
- Nginx가 요청 본문을 5MB까지만 받아서([배포 설정](deployment.md) 2장) 1시간짜리 파일(약 15MB)은 올릴 수 없어요. 그래서 나눠요
- 파일 번호(`seq`)는 녹음 안에서 1부터 매겨요. 글 묶음 번호(`partNo`)와는 따로 가요
- 압축은 끊지 않고 이어서 하고 받아 적는 파일만 바꿔요. 이어 붙이면 한 파일로 저장한 것과 같아요
- 비트레이트를 올릴 때는 한도를 같이 봐요. 10분 파일은 48kbps에서 약 3.7MB, 64kbps에서 약 4.9MB예요

### 시간 맞추기

- 시간 기준은 글과 같아요. 글자 변환에 넣는 소리를 그대로 인코더에도 넣고, 파일마다 녹음 시작부터 몇 ms에서 시작해 몇 ms에서 끝났는지(`startMs`·`endMs`)를 같이 올려요. 서버는 이 값과 카드의 `startMs`·`endMs`로 구간을 찾아요
- 글자 변환이 밀려서 건너뛴 소리가 있으면 그 길이만큼 음성 파일에 무음을 채워요. 그래야 파일 안의 위치와 글의 시간이 맞아요
- 10분은 인코더에 들어간 소리 길이로 세요
- 앱이 녹음 중에 죽어서 파일을 끝맺지 못했으면, 끝 시각은 조각 수로 계산해요

## 3. 올리기

- 글 묶음을 올린 다음에, 그때까지 다 쓴 음성 파일을 번호 순서대로 올려요. 1시간마다(그리고 녹음이 끝날 때) 글 묶음 하나와 음성 파일 여러 개(1시간이면 6개)가 올라가요. 글이 먼저 가야 카드가 늦어지지 않아요
- 음성 올리기가 실패해도 다음 글 묶음은 막지 않아요. 음성은 따로 다시 시도해요
- 올리고 나면 폰의 음성 파일은 지워요
- 폰에 둔 음성(올리기 실패, "Wi-Fi에서 올리기")은 앱이 살아 있는 동안 올려요. 화면에 없어도(백그라운드) 올라가요. 안드로이드가 앱을 완전히 끈 뒤에는 다음에 앱을 열 때 올라가요
- 녹음이 끝난 지 7일이 지나도 못 올린 파일은 폰에서 지워요
- 탈퇴하면 폰에 남은 음성을 올리지 않고 지워요
- 로그아웃할 때는 아래 "로그아웃할 때"를 따라요

### 로그아웃할 때

올릴 수 있는 것은 올리고, 올리지 못한 것만 폰에서 지워요. 글과 음성이 같은 원칙이에요.

| 로그아웃할 때 상황 | 글 | 음성 | 결과 |
| --- | --- | --- | --- |
| 녹음 중, Wi-Fi이거나 "지금 올리기"를 고름 | 마감해 올림 | 올림 | 카드와 음성이 모두 남음 |
| 녹음 중, 모바일 데이터이고 "Wi-Fi에서 올리기"를 고름 | 마감해 올림 | 올리지 못한 파일은 지움 | 카드는 생김. 음성은 이미 올라간 구간의 카드에만 붙음 |
| 녹음 중, 인터넷이 안 됨 | 올리지 못한 묶음은 지움 | 지움 | 앞서 올라간 부분만 카드가 됨 |
| 녹음 중이 아님, 올리지 못한 글이나 음성이 폰에 남음 | 지움 | 지움 | 위와 같음 |
| 남은 것이 없음 | - | - | - |

- 폰에 남겨 두면 다음에 로그인한 계정으로 올라갈 수 있어서, 토큰을 지우기 전에 지워요
- 이미 서버에 올라간 글과 음성은 그대로 둬요. 로그아웃은 탈퇴가 아니에요
- 음성이 지워진 구간의 카드에는 음성이 붙지 않아요

로그아웃 확인 창에서 미리 알려요.

| 상황 | 문구 |
| --- | --- |
| 녹음 중, 음성 저장을 켬 | 녹음 중이에요. 로그아웃하면 녹음이 멈춰요. 글은 올리고, 올리지 못한 음성은 지워져요. |
| 녹음 중, 음성 저장을 끔 | 녹음 중이에요. 로그아웃하면 녹음이 멈추고, 지금까지 녹음한 내용은 올린 뒤 로그아웃돼요 |
| 녹음 중이 아님, 올리지 못한 글이나 음성이 폰에 남음 | 아직 올리지 못한 녹음이 있어요. 로그아웃하면 지워져요. |

## 4. 카드 구간 음성

- 전체 파일은 7일 뒤에 사라지니, 그 전에 서버가 카드 구간만 잘라 따로 저장해요
- 카드가 생겼을 때와 음성 파일이 올라왔을 때, 둘 다 갖춰진 쪽에서 잘라요. 어느 쪽이 먼저 와도 돼요
- 카드 구간 앞뒤로 0.5초씩 여유를 둬요
- 카드 구간이 음성 파일 여러 개에 걸치면 조각을 이어 붙여요. 구간을 덮는 파일이 모두 올라온 뒤에 잘라요
- 카드 구간 음성은 카드가 있는 동안 두고, 카드를 지울 때 같이 지워요
- 자르는 범위는 카드 `startMs - 0.5초`(0보다 작으면 0)부터 `endMs + 0.5초`까지예요. 마지막 묶음까지 받은 녹음이면 끝은 마지막 음성 파일의 `endMs`를 넘지 않게 줄여요
- 범위에 걸치는 조각(0.064초)을 모두 넣어요. 그래서 실제 음성은 범위보다 조금 길 수 있고, 그 길이(조각 수 × 64ms)를 `cards.audio_duration_ms`에 적어요
- 서버는 요청에 답한 뒤 따로 잘라요. 음성 올리기와 감지 결과 응답이 자르기를 기다리지 않아요. 자르다 실패하면 한 시간마다 도는 확인 때 다시 잘라요(전체 파일이 남아 있는 7일 동안)

### 저장 위치

만화 이미지와 같은 버킷(`lolog-comics`, [배포 설정](deployment.md) 5장)에 둬요. 새 버킷을 만들지 않아 서버 설정이 바뀌지 않아요. 모두 `users/{userId}/` 아래라 탈퇴할 때 한 번에 지워져요.

| 무엇 | 객체 키 |
| --- | --- |
| 전체 녹음 파일 | `users/{userId}/recordings/{recordingId}/audio/{seq}.aac` |
| 카드 구간 음성 | `users/{userId}/cards/{cardId}/audio.aac` |

## 5. 보관과 삭제

| 무엇 | 언제 지우나 |
| --- | --- |
| 전체 녹음 파일(서버) | 녹음이 끝난 때부터 7일 뒤. 녹음 하나의 파일은 한꺼번에 지워요 |
| 카드 구간 음성(서버) | 카드를 지울 때 |
| 폰의 음성 파일 | 서버에 올린 뒤. 못 올렸으면 녹음이 끝난 때부터 7일 뒤. 로그아웃하거나 탈퇴하면 그때 |
| 탈퇴 | 그 회원의 전체 녹음 파일과 카드 구간 음성을 모두 지워요 |

- 서버는 한 시간마다 확인해서 7일이 지난 녹음의 전체 파일을 지워요
- 녹음이 끝난 때는 녹음 시작 시각에 전체 길이를 더한 시각이에요. 끝 묶음이 오지 않은 녹음은 받은 묶음까지의 길이로 세요

## 6. API

`/api`(메인 백엔드)이고 로그인이 필요해요.

| 메서드 | 주소 | 하는 일 | 요청 | 응답 |
| --- | --- | --- | --- | --- |
| POST | /api/recordings | 글 묶음 올리기(이미 있는 API). 음성 저장을 켰는지 `audioSaved`로 같이 보내요 | RecordingUploadRequest([API DTO](api-dto.md)) | 202 |
| PUT | /api/recordings/{id}/audio/{seq} | 음성 파일 하나 올리기 | multipart `file`(audio/aac), `startMs`, `endMs` | 204 |

- `audioSaved`는 true·false예요. 없으면 false로 봐요(예전 앱). 녹음 중에는 못 바꾸니 묶음마다 같은 값을 보내요. 서버는 이 값으로 "음성 저장을 끈 녹음"과 "음성이 아직 안 올라온 녹음"을 구분해요
- 서버는 첫 글 묶음의 `audioSaved`를 녹음에 저장해요. 그 뒤 묶음에 다른 값이 와도 바꾸지 않아요
- 서버는 ADTS 머리말(조각마다 붙는 시작 표시)로 AAC인지 확인해요. 파일 끝까지 조각으로 나눠지지 않으면 400(field `file`)이에요
- `{id}`는 글 묶음을 올릴 때 응답으로 받은 `recordingId`예요. 그래서 음성은 그 녹음의 첫 글 묶음이 올라간 뒤에 올릴 수 있어요
- `{seq}`는 녹음 안에서 1부터 매긴 음성 파일 번호예요. 같은 번호를 다시 올리면 덮어써요. 다시 시도해도 안전해요
- `startMs`·`endMs`는 녹음 시작부터의 밀리초이고, 0 ≤ startMs < endMs예요

### 오류 코드

| 코드 | HTTP | 언제 |
| --- | --- | --- |
| INVALID_REQUEST | 400 | 번호나 시간 값이 맞지 않음, AAC 파일이 아님, 음성 저장을 켜지 않은 녹음 |
| RECORDING_NOT_FOUND | 404 | 녹음이 없거나 내 녹음이 아님 |
| PAYLOAD_TOO_LARGE | 413 | 파일이 5MB 초과(Nginx 한도와 같게 맞춤) |

- 학교 쪽 Nginx의 본문 한도는 우리가 볼 수 없어요. 배포한 뒤에 음성 파일이 실제로 올라가는지 한 번 확인해요
