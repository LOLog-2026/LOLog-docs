# 기능 명세

[요구사항](requirements.md) 문서의 P0 기능을 기능 ID마다 화면, 입력, 처리, 출력, 예외, 관련 API로 정리했어요. 화면 이름은 화면 디자인이 나오면 맞춰요.

## 1. 인증

### FR-AUTH-01 이메일 가입·로그인

| 항목 | 내용 |
| --- | --- |
| 화면 | 가입 화면, 로그인 화면 |
| 입력 | 이메일, 비밀번호(가입할 때는 비밀번호 확인과 메일로 받은 인증번호도) |
| 처리 | 인증번호: 가입 화면에서 "인증번호 받기"를 누르면 그 이메일로 6자리 번호를 보낸다. 번호는 10분 동안 쓸 수 있고, 다시 받으면 전 번호는 못 쓴다. 다시 받기는 60초에 한 번이다. 이미 가입된 이메일이면 번호 대신 "이미 가입된 계정" 안내 메일을 보내고, 앱에는 어느 쪽인지 알리지 않는다(남이 가입 여부를 알아내지 못하게). 가입: 이메일 형식과 비밀번호 규칙을 검사하고, 인증번호가 맞는지 확인한 뒤, 이미 가입된 이메일인지 확인하고 계정을 만든다. 번호를 5번 틀리면 그 번호는 못 쓴다. 비밀번호는 암호화해서 저장한다. 로그인: 이메일과 비밀번호가 맞는지 확인하고 토큰을 준다 |
| 출력 | 토큰을 받고 홈 화면으로 간다. 처음 가입이면 권한 안내를 거쳐 홈으로 간다 |
| 예외 | 이메일 형식이 틀림 → 입력 칸에 안내. 비밀번호 규칙에 안 맞음(8~64자, 영문·숫자 포함) → 안내. "인증번호 받기"를 누름 → 결과와 관계없이 "메일을 확인해 주세요". 60초 안에 다시 받기 → "잠시 뒤에 다시 받아 주세요". 인증번호가 틀림 → "인증번호가 맞지 않아요". 인증번호가 만료됐거나 5번 틀림 → "인증번호를 다시 받아 주세요". 이미 가입된 이메일(소셜 로그인으로 가입한 경우 포함) → "이미 가입된 계정이에요. 처음 가입한 방법으로 로그인해 주세요". 로그인 정보가 틀림 → "이메일 또는 비밀번호가 맞지 않아요"(어느 쪽이 틀렸는지는 알리지 않음) |
| 관련 API | POST /auth/email/code, POST /auth/signup, POST /auth/login |

### FR-AUTH-02 소셜 로그인

| 항목 | 내용 |
| --- | --- |
| 화면 | 로그인 화면의 구글·네이버 버튼 |
| 입력 | 각 회사 로그인 창에서 사용자 동의 |
| 처리 | 앱이 그 회사 SDK로 로그인해 받은 토큰을 인증 서비스로 보낸다. 인증 서비스는 그 회사에 토큰이 맞는지 확인하고, 처음 온 사용자면 계정을 만든 뒤 우리 토큰을 준다 |
| 출력 | 토큰을 받고 홈 화면으로 간다. 처음 가입이면(isNewUser가 true) 권한 안내를 거쳐 홈으로 간다 |
| 예외 | 사용자가 로그인 창을 닫음 → 로그인 화면에 그대로 있는다. 그 회사 확인 실패 → "로그인하지 못했어요. 다시 시도해 주세요" |
| 같은 이메일 | 한 이메일에는 계정 하나만 둔다. 소셜 계정의 이메일로 이미 가입된 계정이 있으면 새로 만들지 않고 "이미 가입된 계정이에요. 처음 가입한 방법으로 로그인한 뒤 설정에서 연결해 주세요"라고 안내한다 |
| 관련 API | POST /auth/social/{provider} |

### FR-AUTH-03 로그인 유지

| 항목 | 내용 |
| --- | --- |
| 화면 | 없음(앱이 알아서 처리) |
| 입력 | 폰에 저장해 둔 리프레시 토큰 |
| 처리 | 액세스 토큰(짧게)과 리프레시 토큰(길게)을 폰에 안전하게 저장한다. API가 액세스 토큰 만료로 거절하면 앱이 리프레시 토큰으로 새 토큰을 받고 그 요청을 다시 보낸다. 만료 시간은 액세스 30분, 리프레시 14일 |
| 출력 | 사용자는 다시 로그인하지 않고 계속 쓴다 |
| 예외 | 리프레시 토큰도 만료되거나 무효 → 로그인 화면으로 보낸다 |
| 관련 API | POST /auth/refresh |

### FR-AUTH-04 로그아웃

| 항목 | 내용 |
| --- | --- |
| 화면 | 설정 화면 |
| 입력 | 로그아웃 버튼 |
| 처리 | 서버는 리프레시 토큰을 무효로 하고 이 폰의 푸시 토큰을 지운다. 앱은 저장한 토큰을 지운다. 녹음 중이면 "녹음 중이에요. 로그아웃하면 녹음이 멈추고, 지금까지 녹음한 내용은 올린 뒤 로그아웃돼요"라고 안내하고, 확인하면 녹음을 마감해 올린 뒤 로그아웃한다 |
| 출력 | 로그인 화면으로 간다 |
| 예외 | 서버에 닿지 않음 → 앱의 토큰만 지우고 로그인 화면으로 간다 |
| 관련 API | POST /auth/logout, DELETE /api/devices/fcm-token |

### FR-AUTH-05 회원 탈퇴

| 항목 | 내용 |
| --- | --- |
| 화면 | 설정 화면 → 탈퇴 확인 창 |
| 입력 | 탈퇴 버튼, 확인 |
| 처리 | 회원 정보는 소프트 삭제(삭제 표시만 하고 행은 남김)한다. 그 사용자의 카드, 만화와 만화 이미지, 남아 있는 대화 텍스트, 작업 기록, 푸시 토큰, 리프레시 토큰은 모두 지운다. 진행 중인 이야기 감지·만화 작업은 취소한다 |
| 출력 | 로그인 화면으로 간다 |

| 관련 API | DELETE /auth/me. 서버끼리: DELETE /internal/users/{id} |

### FR-AUTH-06 소셜 계정 연결·해제

| 항목 | 내용 |
| --- | --- |
| 화면 | 설정 화면의 계정 연결(구글·네이버) |
| 입력 | 연결할 회사의 로그인 창에서 사용자 동의 |
| 처리 | 로그인한 상태에서 앱이 그 회사 SDK로 받은 토큰을 인증 서비스로 보낸다. 인증 서비스는 토큰을 확인하고 그 소셜 계정을 지금 계정에 연결한다. 그다음부터 그 소셜 계정으로 로그인하면 같은 계정으로 들어간다. 연결된 회사의 "연결 끊기"를 누르면 인증 서비스가 그 연결을 지운다 |
| 출력 | 연결된 계정 목록에 표시된다 |
| 예외 | 그 소셜 계정이 이미 다른 LOLog 계정에 쓰이고 있음 → 연결하지 않고 "이미 다른 계정에 연결된 소셜 계정이에요"라고 안내한다. 같은 회사 계정이 이미 연결돼 있음 → 연결 버튼 대신 "연결됨"과 "연결 끊기"를 보여 준다. 비밀번호가 없는 계정의 마지막 소셜 연결 끊기 → 끊지 않고 "다른 로그인 방법을 먼저 연결해 주세요"라고 안내한다 |
| 관련 API | GET /auth/me, POST /auth/me/social/{provider}, DELETE /auth/me/social/{provider} |

### FR-AUTH-07 비밀번호 찾기·바꾸기

| 항목 | 내용 |
| --- | --- |
| 화면 | 로그인 화면의 "비밀번호 찾기" → 비밀번호 찾기 화면. 설정 화면의 "비밀번호 바꾸기" |
| 입력 | 찾기: 이메일, 메일로 받은 인증번호, 새 비밀번호(확인 포함). 바꾸기: 지금 비밀번호, 새 비밀번호(확인 포함) |
| 처리 | 찾기: "인증번호 받기"를 누르면 비밀번호가 있는 계정에는 6자리 번호를, 소셜로만 가입한 계정에는 "소셜로 가입한 계정" 안내를 메일로 보낸다. 가입 안 된 이메일이면 아무것도 보내지 않는다. 앱에는 어느 쪽인지 알리지 않고, 늘 바로 "메일을 확인해 주세요"를 보여 준다(메일은 그 뒤에 보낸다). 번호 규칙은 가입과 같다. 번호가 맞으면 새 비밀번호로 바꾸고 그 계정의 모든 기기 로그인을 끊는다. 바꾸기: 지금 비밀번호가 맞으면 새 비밀번호로 바꾸고, 다른 기기의 로그인은 끊고 지금 기기는 새 토큰으로 계속 쓴다 |
| 출력 | 찾기: "비밀번호를 바꿨어요. 새 비밀번호로 로그인해 주세요"와 함께 로그인 화면으로 간다. 바꾸기: "비밀번호를 바꿨어요" 안내 |
| 예외 | 새 비밀번호 규칙에 안 맞음 → 가입과 같은 안내. 60초 안에 다시 받기 → "잠시 뒤에 다시 받아 주세요". 인증번호가 틀림 → "인증번호가 맞지 않아요". 만료·5번 틀림 → "인증번호를 다시 받아 주세요". 지금 비밀번호가 틀림 → "지금 비밀번호가 맞지 않아요". 소셜로만 가입한 계정 → 설정에 "비밀번호 바꾸기"를 보여 주지 않는다 |
| 관련 API | POST /auth/password/reset/code, POST /auth/password/reset, POST /auth/me/password |

## 2. 녹음과 글자 변환

### FR-REC-01·02 녹음 시작과 끝, 백그라운드 녹음

| 항목 | 내용 |
| --- | --- |
| 화면 | 홈의 마이크 버튼 → 녹음 화면, 상단 "녹음 중" 알림 |
| 입력 | 녹음 시작·끝 버튼. 상단 알림에서도 끝낼 수 있다 |
| 처리 | 시작하면 앱이 포그라운드 서비스를 켜고 상단 알림을 띄운다. 화면이 꺼지거나 다른 앱을 써도 서비스가 녹음을 이어 간다. 끝내면 서비스를 끄고 업로드(FR-UP-01)로 넘어간다 |
| 출력 | 녹음 중 표시와 지난 시간 |
| 예외 | 마이크 권한 없음 → 시작하지 않고 권한을 요청한다. 알림 권한 없음 → 권한을 요청한다. 전화가 오거나 시스템이 서비스를 끄면 그때까지 쌓인 문장으로 녹음을 마감한다 |
| 관련 API | 없음(폰 안에서 처리) |

### FR-REC-03\~06, 08 글자 변환

| 항목 | 내용 |
| --- | --- |
| 화면 | 없음(녹음 중 뒤에서 처리) |
| 입력 | 마이크 소리 |
| 처리 | 마이크 소리를 링버퍼에 담는다. 먼저 실시간 크기 맞춤으로 작은 소리를 키운 뒤, 음성 구간 감지(VAD)가 말소리가 있는 구간만 sherpa-onnx로 넘긴다. 구간 앞의 소리를 0.3초 더 붙여 말이 잘리지 않게 한다. 붙이는 소리는 앞 구간의 끝을 넘지 않는다. 조용한 구간은 넘기지 않는다. 구간이 20초를 넘으면 강제로 자른다. 문장이 나오면 녹음 시작부터의 시작·끝 시간(앱이 받은 샘플 수로 계산)을 붙여 폰에 쌓는다. 음성 저장을 켜지 않았으면 글자로 바꾼 소리는 바로 버려서 음성이 폰 밖으로 나가지 않게 한다. 켰으면 크기를 맞춘 소리를 파일로도 남긴다([음성 저장](audio.md)) |
| 출력 | 문장 목록(시작 시간, 끝 시간, 글) |
| 예외 | 빈 인식 결과는 쌓지 않는다. 구간끼리 겹치지 않으므로 글자를 비교해 중복을 지우는 처리는 하지 않는다 |
| 관련 API | 없음(폰 안에서 처리) |
| 설정값 | 아래 값은 오픈소스 데이터(FLEURS ko, Zeroth-Korean)로 측정해 정했다([측정 결과](https://github.com/LOLog-2026/LOLog-ai/tree/develop/experiments/261109-stt-ondevice)). |
| VAD | silero, 16kHz, 창 512샘플. 민감도 0.6, 쉼 0.8초, 최소 말 길이 0.25초, 최대 말 길이 20초, 앞 여유 0.3초 |
| 크기 맞춤 | VAD 앞에서 512샘플(32ms)마다 계산하고, 키운 소리를 VAD와 인식기에 같이 넘긴다. 계산 방법은 아래 순서를 따른다. ① 프레임 RMS `r`을 구한다. ② 바닥 소음 `noise`는 첫 프레임 RMS로 시작한다. `r < noise`면 `noise = r`로, 아니면 `noise *= 1.002`로 바꾼다. ③ 말소리 크기 `level`은 -23dBFS로 시작하고, `r > 2*noise`인 프레임에서만 `level = 0.9*level + 0.1*r`로 바꾼다. ④ 이득은 `g = clamp(10^(-23/20)/level, 1, 20)`로 구하고, 다시 `g = max(1, min(g, 10^(-50/20)/noise))`로 제한한다. ⑤ 프레임 안에서 이전 이득부터 새 이득까지 선형으로 바꿔 곱하고, [-1, 1]로 자른다 |
| 강제 자르기 | sherpa-onnx VAD의 최대 말 길이 설정은 구간을 실제로 자르지 않는다(측정에서 132.8초 구간도 나왔다). 그래서 앱에서 직접 자른다. 구간이 20초를 넘으면 10~20초 사이에서 소리가 가장 작은 32ms 프레임을 찾아 거기서 자른다 |
| 인식기 | SenseVoice int8, 언어 ko, ITN 켬, 2스레드 |
| 측정 결과 | 비교 기준은 민감도 0.5, 쉼 0.5초, ITN 켬, 크기 맞춤 없음으로 둔 설정이다. 2026-11-10 앱 코드는 쉼이 0.25초이고 ITN이 꺼져 있다. 쉼 0.25초는 dev에서 0.6%p쯤 더 나쁘고, ITN 끔은 차이가 0.05%p 이내다. 아래는 비교 기준과 추천 설정의 글자 오류율(CER)이다. 5분 긴 녹음 7.95 → 5.93%, 작은 소리 13.15 → 6.02%, 붐비는 곳 9.29 → 8.63%, 웅성거림 10dB 15.12 → 14.38%. 처리 속도(RTF 0.017~0.025)는 같다 |
| 한계 | 옆에서 TV나 다른 사람이 계속 말하는 곳은 오류율이 약 67%다. 이 문제는 설정으로 풀리지 않는다 |

## 3. 업로드

### FR-UP-01·02 녹음 글 올리기

| 항목 | 내용 |
| --- | --- |

## 4. 이야기 감지와 카드

### FR-CARD-01\~04 이야기 찾기와 카드 만들기

| 항목 | 내용 |
| --- | --- |
| 화면 | 없음(서버에서 처리). 결과는 보관함과 알림으로 보인다 |
| 입력 | 올라온 묶음의 문장 목록 |
| 처리 | 서버가 먼저 LLM으로 기록할 만한 이야기(웃김·황당·추억 중 하나)를 찾고, 찾은 이야기 부분만 다시 LLM에 보내 문맥으로 대사마다 화자를 나눈다. 화자는 처음엔 "화자1", "화자2"로 붙고, 카드당 1~4명이다(만화 한 컷에 말풍선을 넣을 자리 때문에 콘티 형식에 맞춤). 묶음 경계에 걸친 이야기는 아래 "묶음 경계" 줄처럼 다음 묶음과 이어 읽어 하나로 찾는다. 이야기마다 카드(종류, 요약(제목으로 쓰는 한 문장, 30자 이하), 시간 범위, 화자별 대사)를 만들어 보관함에 넣는다. 감지가 끝나면 detect 큐 메시지는 지운다. 이야기가 아닌 원래 글도 바로 지운다. 다음 묶음으로 넘긴 끝부분만 다음 묶음을 처리한 뒤 지운다 |
| 묶음 경계 | ① 묶음이 오면 앞 묶음에서 넘겨받은 부분을 앞에 붙여 읽는다. ② LLM은 이야기마다 시작·끝 시간과 끝났는지를 돌려준다. ③ 앞 묶음에서 이미 카드가 된 이야기는 버린다. 메인 백엔드가 감지 결과를 받을 때, 같은 녹음에 이미 있는 카드와 시간 범위가 겹치는 카드를 버린다. ④ 끝이 이번 묶음의 마지막 5분 안에 있거나 끝나지 않았다고 본 이야기는 카드로 만들지 않고 다음 묶음으로 넘긴다. 묶음 뒤를 봐야 진짜 끝인지 알 수 있어서다. ⑤ 넘길 시작점은 "마지막 5분의 시작"과 "넘긴 이야기 중 가장 이른 시작" 중 더 이른 쪽이고, 그 뒤의 글은 다음 묶음을 처리할 때까지 지우지 않는다. ⑥ 마지막 묶음(isLast)은 남은 이야기를 모두 카드로 만든다. ⑦ 다음 묶음이 1시간 10분 안에 안 오면 넘겨 둔 부분만 따로 처리한다(마지막 묶음처럼 모두 카드로 만든다) |
| 출력 | 카드 0개 이상. 새 카드가 있으면 푸시(FR-NOTI-01) |
| 예외 | 이야기가 하나도 없음 → 카드를 만들지 않고 알림은 보내지 않는다. 처리 중 멈춤 → 다시 시도하고, 3번 넘게 실패하면 실패로 표시한다. 실패한 묶음의 글은 바로 지우고 다음 묶음은 넘겨받을 것 없이 처리한다. 녹음은 감지한 묶음이 모두 실패했을 때만 실패로 표시한다 |
| 관련 API | GET /api/recordings, GET /api/recordings/{id}. 워커용: /internal/recordings/{id}/cards |

## 6. 4컷만화

### FR-COMIC-01\~04, 06 만화 요청과 진행 상태

| 항목 | 내용 |
| --- | --- |
| 화면 | 카드 자세히 화면의 만화 만들기 버튼, 진행 상태 표시 |
| 입력 | 카드 ID |
| 처리 | 서버가 만화 작업을 만들고 바로 답한다. 뒤에서 LLM이 카드로 4칸 콘티(칸별 장면, 인물, 대사)를 만든다. 먼저 등장인물마다 그 이야기에서 쓸 외모 설명을 정하고, 그림 설명에는 "화자1" 같은 내부 이름 대신 이 설명을 모든 컷에 똑같이 넣는다. 4칸은 1컷 빌드업, 2컷 전개, 3컷 펀치라인, 4컷 리액션으로 나눈다. 콘티를 만들 때 대사는 말풍선에 들어갈 만큼 줄이고, 대화에 나온 실명·주소는 뺀다. 그림으로 넘기기 전에 콘티를 검사한다. 정확히 4컷인지, 대사가 말풍선에 들어갈 길이인지, 그림 설명에 "화자1" 같은 내부 이름이 섞이지 않았는지 보고, 어기면 LLM에 한 번 다시 묻고 그래도 안 되면 실패로 처리한다. 검사를 통과하면 이미지 모델이 컷 4개를 하나씩 글자와 말풍선 없이 그리고, 워커가 컷마다 화자 위치에 말풍선을 그려 콘티의 대사를 넣은 뒤 세로 4칸 한 장으로 합친다. 콘티 형식과 검사 규칙은 [콘티 형식](storyboard.md)에 있다. 상태는 대기 → 콘티 → 그림 → 완료 순서로 바뀐다 |
| 출력 | 진행 상태. 완성되면 4컷 이미지와 푸시(FR-NOTI-02) |
| 예외 | 같은 카드에 진행 중인 작업이 있음 → 새 요청을 받지 않는다(409 COMIC\_IN\_PROGRESS, 아래 횟수 한도보다 먼저 본다). 같은 카드로 이미 3번 만들었음(실패한 만화는 세지 않고, 지운 만화는 셈) → 새 요청을 받지 않는다(409 COMIC\_LIMIT). 만들기 실패 → "실패"로 표시한다 |
| 기준 | 컷 배치는 세로 4칸. 말풍선 대사는 하나에 25자(공백 포함), 컷당 최대 2개(인물이 3명인 컷은 1개) |
| 관련 API | POST /api/cards/{id}/comics, GET /api/comics/{id} |

### FR-CHAR-01·02 화자 그림 붙이기(기본 화자·프로필 캐릭터)

| 항목 | 내용 |
| --- | --- |
| 화면 | 카드 자세히 화면에서 화자를 누르면 뜨는 팝업(기본 탭, 프로필 탭), 프로필 화면의 프로필 캐릭터 만들기 |
| 입력 | 기본 화자 24명 중 하나, 또는 쓸 수 있는 그림이 있는 내 프로필 캐릭터나 친구의 프로필 캐릭터 하나. 프로필 캐릭터 만들기는 본인 사진 한 장 |
| 처리 | 고른 그림을 카드의 그 화자에 붙인다. 만화를 만들 때 그림이 붙은 화자는 외모를 LLM이 정하지 않고 그 그림의 외모 글을 쓰고, 그 화자가 나오는 컷마다 그림을 참조 이미지로 넣어 같은 얼굴로 그린다. 본인 사진은 한 번 웹툰 화풍 그림으로 바꾸고 원본은 바로 지운다. 친구의 캐릭터는 친구가 만든 것을 가져와 쓴다 |
| 기본값 | 아무 그림도 붙이지 않으면 지금과 같다(LLM이 외모를 정함) |
| 예외 | 한 카드에서 같은 그림을 두 화자에 붙임 → 막는다(400 DUPLICATE\_CHARACTER). 쓸 수 있는 그림이 없는 프로필 캐릭터 → 막는다(409 CHARACTER\_NOT\_READY). 친구가 아닌 사람의 캐릭터 → 막는다(400 UNKNOWN\_CHARACTER). 만드는 중에 또 올림 → 409 CHARACTER\_IN\_PROGRESS. 만화를 만들 때 붙어 있던 캐릭터가 지워졌거나 친구가 끊겼으면 그 화자는 그림 없이 그린다 |
| 관련 문서 | [화자 그림](characters.md) |

## 10. 음성 저장

### FR-REC-09·FR-UP-03·FR-EXT-01 음성 저장

| 항목 | 내용 |
| --- | --- |
| 화면 | 녹음 버튼이 있는 화면의 "음성도 저장" 체크, 모바일 데이터 창("지금 올리기"·"Wi-Fi에서 올리기"), 녹음 중 상단 알림과 녹음 화면 아래 글의 문구 |
| 입력 | "음성도 저장" 체크, 모바일 데이터 창의 선택, 마이크 소리 |
| 처리 | 체크를 켜고 녹음하면 앱이 글자 변환에 넣는 소리(크기를 맞춘 소리)를 AAC 파일로도 쓴다. 파일은 10분마다 새 번호로 넘어간다. 글 묶음을 올린 다음에 그때까지 다 쓴 음성 파일을 번호 순서대로 올린다. 서버는 파일을 저장하고, 카드가 생기면 카드 구간(앞뒤 0.5초 여유)만 잘라 카드 음성으로 따로 둔다. 녹음이 끝난 지 7일이 지난 전체 파일은 서버가 지운다 |
| 출력 | 카드 구간 음성(카드가 있는 동안 보관) |
| 기본값 | 체크는 끔이다. 고른 값은 폰이 기억하고, 녹음 중에는 바꿀 수 없다 |
| 예외 | 모바일 데이터로 녹음을 시작함 → 창으로 묻는다. "Wi-Fi에서 올리기"면 글만 올리고 음성은 폰에 두었다가 Wi-Fi에서 올린다. 녹음 중에 모바일 데이터로 바뀜 → 묻지 않고 그 뒤 음성은 Wi-Fi를 기다린다. 음성 올리기 실패 → 글 묶음은 막지 않고 음성만 다시 시도한다. 녹음이 끝난 지 7일이 지나도 못 올림 → 폰에서 지운다. 파일이 5MB 초과 → 413 PAYLOAD\_TOO\_LARGE. 음성 저장을 켜지 않은 녹음에 올림 → 400 INVALID\_REQUEST |
| 관련 API | POST /api/recordings(audioSaved), PUT /api/recordings/{id}/audio/{seq} |
| 관련 문서 | [음성 저장](audio.md) |

추가 구현(P1·P2) 기능은 범위가 정해지면 같은 모양으로 더할게요.
